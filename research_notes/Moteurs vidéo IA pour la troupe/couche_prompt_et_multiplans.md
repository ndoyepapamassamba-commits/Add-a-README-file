# La couche « prompt et mise en scène » des générateurs vidéo IA, et la fabrication de sketchs narratifs multi-plans de 25–60 s (état au 16/10/2026)

Périmètre : (1) comment Veo, Kling, Grok Imagine, Sora, Wan (et le nouveau Gemini Omni Flash) interprètent prompts et images : réécriture LLM, guides officiels, syntaxes (dialogue, SFX, ambiance, négatifs, JSON) ; (2) l'état de l'art du multi-plans et de la vidéo longue à personnages constants (produits et recherche), le timing comique au montage, et le format intermédiaire (shot list) des pipelines. Le but est de concevoir notre propre couche « réalisateur » pour des sketchs TikTok 9:16 de 25–60 s, avec 2–4 personnages cartoon ouest-africains, des dialogues en français et la structure accroche → escalade → twist → chute figée sur un visage choqué face caméra.

Méthode : sources consultées le 16/10/2026. Je privilégie les docs officielles (Google Cloud / Gemini API, docs.x.ai, kling.ai, GitHub Wan, cookbook OpenAI) et arXiv. Je signale les blogs d'éditeurs tiers (fal, Atlas Cloud, Atlabs, Morphic…) comme tels : leurs syntaxes relèvent de la convention communautaire, pas d'un comportement documenté. Pour les papiers 2026 marqués « (résumé seul) », je n'ai lu que l'abstract ou l'extrait de recherche.

## 1. Réécriture de prompt (prompt enhancer) et syntaxes officielles de prompt

### Takeaway
Veo et Wan ont une étape de réécriture par LLM documentée officiellement. Pour Veo, c'est un « prompt rewriter » Gemini (`enhancePrompt`, activé par défaut), qui ajoute description visuelle, mouvements de caméra, transcription des dialogues et effets sonores. Pour Wan, c'est `prompt_extend` via Qwen. Pour Kling, Grok Imagine et Sora, je n'ai trouvé aucune documentation publique d'un réécriveur. Les guides officiels convergent vers une structure [caméra/cadrage] + sujet + action + contexte + style/ambiance, avec l'audio dans des phrases séparées : dialogue entre guillemets et attribué à un locuteur nommé, « SFX: », « Ambient noise: ». Deux faits datés changent le paysage : l'API Sora a fermé le 24/09/2026, et Google recommande désormais Gemini Omni Flash plutôt que Veo comme modèle vidéo par défaut dans l'API Gemini.

### Cited Findings

**Veo (Google) : le réécriveur de prompt**
- Veo propose un « LLM-based prompt enhancement tool, also known as a prompt rewriter ». Il peut réécrire le prompt pour y ajouter « video description, camera motions, transcription, and sound effects » — [Google Cloud, Turn off Veo's prompt rewriter](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/turn-the-prompt-rewriter-off) (texte obtenu via les extraits de recherche des versions EN/DE/FR de la page : le corps de page n'a pas pu être rendu par mon outil ; page « Last updated 2026-10-15 UTC »).
- Paramètre REST : `enhancePrompt` (booléen) dans l'objet `parameters` ; `enhance_prompt=False` dans le SDK Python ; valeur par défaut True. La page anglaise parle explicitement d'une activation par défaut pour `veo-2.0-generate-001`. Le défaut exact pour Veo 3/3.1 est à confirmer — [Google Cloud, prompt rewriter](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/turn-the-prompt-rewriter-off).
- Selon la doc, désactiver la réécriture peut dégrader « the quality of the videos and how well the output resembles the prompt ». Le prompt réécrit n'est renvoyé dans la réponse API que si le prompt d'origine fait moins de 30 mots — [Google Cloud, prompt rewriter](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/turn-the-prompt-rewriter-off).
- La documentation Vertex existe désormais aussi sous l'étiquette « Gemini Enterprise Agent Platform » (« Turn off Veo on Gemini Enterprise Agent Platform's prompt rewriter ») — [Google Cloud](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/video/turn-the-prompt-rewriter-off).

**Veo : structure officielle du prompt**
- Le guide officiel (mis à jour le 2026-10-15) liste ces éléments : Subject ; Action ; Scene/context (lieu, heure, météo, époque) ; Camera angles and movements (« bird's-eye view », « extreme close-up », « slow zoom in ») ; Lens/optical effects (« shallow depth of field », « rack focus ») ; Visual style (éclairage, ton, palette) ; Temporal elements (ralenti, time-lapse, rythme) ; Cinematic/editing terms (« jump cut », « montage »). Tous les éléments ne sont pas nécessaires dans chaque prompt — [Google Cloud, Veo prompt guide](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/video-gen-prompt-guide).
- Formule officielle du « ultimate prompting guide » Veo 3.1 : **[Cinematography] + [Subject] + [Action] + [Context] + [Style & Ambiance]**. Exemple : « Medium shot, a tired corporate worker, rubbing his temples in exhaustion, in front of a bulky 1980s computer… Retro aesthetic, shot as if on 1980s color film, slightly grainy. » — [Google Cloud Blog, 16/10/2025](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1). Un résultat de recherche date ce billet du 15/10/2025, d'où un léger écart de date.
- La page Gemini API Veo liste comme éléments clés subject, action, style, puis en optionnel camera positioning/motion, composition, focus/lens, ambiance. Elle conseille des adjectifs et adverbes descriptifs, et le mot « portrait » pour accentuer le détail du visage — [Gemini API, Veo](https://ai.google.dev/gemini-api/docs/veo).

**Veo : syntaxe audio et dialogue**
- Guide Vertex : demander l'audio clairement et placer l'audio dans des phrases séparées de la description visuelle. Effets sonores : « the sound of a phone ringing ». Ambiance : « the quiet hum of an office ». Dialogue : attribuer à un locuteur avec « says » / « replies », par exemple « The seasoned detective says: Your story has holes. » et « The nervous informant, sweating under a single bare bulb, replies: I'm telling you everything I know. » — [Google Cloud, Veo prompt guide](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/video-gen-prompt-guide).
- Guide Veo 3.1 : « Use quotation marks for specific speech (e.g., A woman says, "We have to leave now.") » ; « SFX: thunder cracks in the distance » ; « Ambient noise: the quiet hum of a starship bridge » — [Google Cloud Blog](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1).
- Gemini API : « Use quotes for specific speech » (« "This must be the key," he murmured. »). La voix peut mal se prolonger lors d'une extension si elle est absente de la dernière seconde de la vidéo — [Gemini API, Veo](https://ai.google.dev/gemini-api/docs/veo).
- Sous-titres parasites : MIT Technology Review rapporte que Veo 3 ajoute souvent des sous-titres incohérents aux clips dialogués, même quand le prompt demande « no subtitles ». Josh Woodward (Google Labs) a annoncé des correctifs le 9 juin 2025, mais des utilisateurs signalaient encore le problème un mois plus tard. Un chercheur cité (T. Chakrabarty) note que les instructions négatives marchent moins bien que les positives — [MIT Technology Review, 15/07/2025](https://www.technologyreview.com/2025/07/15/1120156/googles-generative-video-model-veo-3-has-a-subtitles-problem).
- Contournement communautaire : le guide Replicate écrit les répliques en « says: … » et ajoute « (no subtitles!) » dans le prompt — [Replicate, Using and prompting Veo 3](https://replicate.com/blog/using-and-prompting-veo-3). Des blogs SEO affirment que les guillemets ou les verbes de parole déclenchent les sous-titres, sans test vérifiable (synthèse de recherche ; aucune source primaire).

**Veo et négatifs**
- Guide Vertex : ne pas écrire « no » ou « don't » (« no walls ») mais lister directement les éléments indésirables (« wall, frame »). Exemple de prompt négatif : « urban background, man-made structures, dark, stormy, or threatening atmosphere » — [Google Cloud, Veo prompt guide](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/video-gen-prompt-guide).
- Le guide Veo 3.1 propose plutôt de décrire positivement ce qu'on veut (« a desolate landscape with no buildings or roads » au lieu de « no man-made structures ») et ne mentionne pas de paramètre négatif séparé — [Google Cloud Blog](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1). Les deux sources Google diffèrent donc légèrement : liste d'éléments dans un champ négatif d'un côté, reformulation positive dans le prompt de l'autre.

**Veo : paramètres de l'API Gemini (contraintes utiles au découpage)**
- Modèles : `veo-3.1-generate-preview`, `veo-3.1-fast-generate-preview` (MAJ janvier 2026), `veo-3.1-lite-generate-preview` (mars 2026). `veo-3.0-*` est marqué déprécié. Durées 4, 6 ou 8 s, avec 8 s obligatoires pour l'extension, les images de référence, le 1080p et la 4K. Formats `16:9` (défaut) ou `9:16`. `referenceImages` : jusqu'à 3 images (Veo 3.1 / 3.1 Fast). `lastFrame` sert à l'interpolation avec `image` — [Gemini API, Veo](https://ai.google.dev/gemini-api/docs/veo).
- Extension : +7 s par pas, jusqu'à 20 fois. L'entrée doit faire ≤ 141 s en 720p, pour une sortie totale ≤ 148 s. L'extension est indisponible sur Lite et limitée au 720p — [Gemini API, Veo](https://ai.google.dev/gemini-api/docs/veo).

**Gemini Omni Flash (Google) : nouveau modèle vidéo recommandé par défaut**
- La page « Video generation » de l'API Gemini (MAJ 2026-06-30) recommande Gemini Omni Flash comme modèle par défaut pour la génération vidéo. Elle met en avant « superior video coherence, multi-input reasoning », la cohérence des personnages et l'édition conversationnelle multi-tours. Veo 3.1 reste disponible — [Gemini API, Video](https://ai.google.dev/gemini-api/docs/video).
- `gemini-omni-1.1-flash` : texte, image, audio et vidéo en entrée ; 16:9 ou 9:16 ; image→vidéo ; interpolation première/dernière image ; images de référence de sujets. **Multi-plans par défaut** : un plan unique exige d'écrire « In a single continuous shot » ou « No scene cuts ». Extension de 10 s par pas, jusqu'à 40 s au total. Références vidéo : jusqu'à 3 clips de ≤ 3 s, dont l'audio est ignoré — [Gemini API, Omni](https://ai.google.dev/gemini-api/docs/omni).
- Conseils de prompt Omni : langage naturel (scène, caméra, lumière, ambiance) ; écrire « No dialogue » pour éviter la parole ; timing en langage naturel (« After 3 seconds, a woman enters the scene ») ou en timecodes (« [0-3s] A person is walking ») ; pour éditer, « Keep everything else the same » ; paramètre optionnel `task` (`text_to_video`, `image_to_video`, `reference_to_video`, `edit`, `extend`) quand le prompt seul ne suffit pas. Le dialogue est possible en extension de vidéos générées par Omni, pas de vidéos uploadées. L'édition et l'extension de vidéos uploadées sont indisponibles dans l'EEE, en Suisse et au Royaume-Uni — [Gemini API, Omni](https://ai.google.dev/gemini-api/docs/omni).

**Kling (Kuaishou)**
- Formule officielle : cœur obligatoire = Subject (apparence, posture) + Subject movement + Scene (premier plan, arrière-plan, décor) ; couches optionnelles = camera language, lighting, atmosphere. Le « camera language » est distinct du contrôle de mouvement caméra. Conseils : mots simples, contenu réalisable en 5–10 s ; les comptes d'objets et les physiques complexes (balle qui rebondit, trajectoire) restent difficiles. La page ne mentionne ni négatifs, ni dialogue, ni optimisation automatique du prompt, mais dit que Kling « extrapolate » à partir du texte — [kling.ai Quickstart, 24/11/2025](https://kling.ai/quickstart/text-to-video-prompt-guide).
- Le blog Kling décrit 6 composantes : Subject, Movement, Scene, Cinematic Language, Lighting, Atmosphere — [kling.ai blog, prompt guide](https://kling.ai/blog/kling-ai-prompt-guide).
- Selon un guide tiers, l'API Kling plafonne prompt et negative prompt à 2 500 caractères chacun — [Atlas Cloud (revendeur)](https://www.atlascloud.ai/blog/guides/kling-ai-video-prompt-guide).
- Dialogue Kling 3.0 selon fal (5/02/2026) : étiquettes de personnage uniques et constantes (pas de pronoms ni de synonymes) ; décrire l'action du personnage avant sa réplique ; un label de ton par personnage, au format `[Character A: Exhausted Partner, trembling frustrated voice]: "..."` ; des connecteurs temporels comme « Immediately, », et éventuellement « this is when the speaker switches » pour éviter que les voix fusionnent. Le modèle gère plusieurs langues, dialectes et accents, ainsi que le code-switching — [fal.ai, Kling 3.0 Prompting Guide](https://blog.fal.ai/kling-3-0-prompting-guide/).
- Lip-sync natif Kling VIDEO 3.0 Omni : **5 langues, chinois, anglais, japonais, coréen et espagnol** (plus dialectes et accents) ; **le français n'y figure pas** au 3/07/2026. Durée 3–15 s. Liaison voix↔personnage : vidéo de référence de 3–8 s, ou multi-images + clip audio de ≥ 3 s, ou « Element Voice Control », avec un audio propre, sans voix superposées. Pour les scènes à plusieurs, garder le nom du locuteur, sa réplique et la note de jeu côte à côte — [kling.ai blog, Omni native lip sync, 3/07/2026](https://kling.ai/blog/kling-video-3-omni-native-lip-sync-audio-guide).

**Grok Imagine (xAI)**
- Docs officielles : `grok-imagine-video-1.5` couvre la génération, l'image→vidéo et la référence→vidéo ; `grok-imagine-video` couvre l'édition vidéo. Durée ≤ 15 s. Mode référence→vidéo : jusqu'à 14 images de référence et 3 références de voix, avec épinglage possible de la première image, de la dernière et d'images en milieu de vidéo. Extension depuis la dernière image, fusionnée en un seul clip. Requêtes asynchrones. Aucun conseil de prompt explicite ni aucune mention de réécriture (pas de champ « revised_prompt ») — [xAI Docs, Video generation](https://docs.x.ai/docs/guides/video-generation).
- Tutoriel tiers : SDK `xai-sdk`, `client.video.generate(prompt, model="grok-imagine-video")`, durée 1–15 s, formats dont 9:16, 480p/720p — [DataCamp](https://www.datacamp.com/tutorial/grok-imagine-api). Clips de 1–15 s, 24 fps — [OpenRouter](https://openrouter.ai/x-ai/grok-imagine-video).
- Un README de revendeur décrit des balises `<IMAGE_N>` pour lier chaque image de référence à un rôle dans le prompt (une image non balisée peut être ignorée ou mélangée), avec 1 à 7 références plus une voix optionnelle, sur une base « Aurora » MoE. Cela **contredit** les 14 références des docs xAI : version ou revendeur différent — [Atlas Cloud (revendeur)](https://www.atlascloud.ai/fr/models/xai/grok-imagine-video-v1.5/reference-to-video).

**Sora (OpenAI) : arrêté**
- OpenAI a annoncé le 24/03/2026 l'arrêt de Sora : l'app et le web ont fermé le 26/04/2026, l'**API le 24/09/2026** — [The Decoder, 28/03/2026](https://the-decoder.com/openai-sets-two-stage-sora-shutdown-with-app-closing-april-2026-and-api-following-in-september/) ; [Engadget](https://engadget.com/ai/openai-is-shutting-down-its-sora-video-generation-app-211023358.html).
- Le guide de prompt Sora 2 (marqué « Updated – March 2026 », archivé) reste une bonne référence méthodologique. Ce que l'API contrôle (modèle, taille, `seconds` = 4/8/12/16/20) ne se règle pas par la prose : demander « plus long » dans le prompt ne change rien. Gabarit : description en prose, puis bloc « Cinematography: », liste « Actions: », bloc « Dialogue: » optionnel. Un mouvement caméra et une action claire par plan ; actions décrites en beats chronométrés (pas comptés, pauses) ; 3–5 couleurs de palette nommées pour stabiliser le rendu entre plans. Les prompts courts laissent plus de liberté, les longs donnent plus de contrôle mais sont moins fidèlement suivis. La réécriture n'est pas documentée — [OpenAI Cookbook, Sora 2 prompting guide](https://developers.openai.com/cookbook/examples/sora/sora2_prompting_guide).

**Wan (Alibaba, open-source) : `prompt_extend`**
- Wan2.1 : « Extending the prompts can effectively enrich the details in the generated videos ». L'option est désactivée par défaut et s'active avec `--use_prompt_extend`. Deux méthodes : `--prompt_extend_method 'dashscope'`, qui appelle `qwen-plus` en T2V et `qwen-vl-max` en I2V, ou `'local_qwen'`, qui utilise `Qwen2.5-14B/7B/3B-Instruct` en T2V et `Qwen2.5-VL-7B/3B-Instruct` en I2V et en first-last-frame. Autres flags : `--prompt_extend_model` et `--prompt_extend_target_lang 'zh'`. Les auteurs disent que leurs évaluations manuelles avec extension battent des modèles fermés et ouverts. Ils recommandent des prompts chinois pour le first-last-frame→vidéo, modèle entraîné surtout sur des paires chinoises — [GitHub Wan2.1](https://github.com/Wan-Video/Wan2.1).
- Wan 2.6 (API DashScope) : le multi-plans s'active avec `shot_type: "multi"` (`single` par défaut), et l'exemple officiel cité l'associe à `prompt_extend: true`. Durées de 5, 10 ou 15 s — [Evolink, Wan 2.6 API Guide (tiers)](https://evolink.ai/blog/wan-2-6-api-guide). Les sources tierces divergent sur l'obligation d'activer `prompt_extend` pour le multi-plans.

**Prompting « JSON »**
- Tendance réelle chez les créateurs : décrire un plan en champs (caméra, lumière, environnement, audio), présentés comme une « shot list » qui aide la cohérence entre clips — [Artlist](https://artlist.io/blog/veo-3-json-prompts/) ; [Atlabs](https://www.atlabs.ai/blog/json-prompting-veo3). Des voix critiques jugent que le format compte peu — [The Creative Possible](https://creativepossible.substack.com/p/should-you-prompt-in-json). La recherche n'a trouvé aucun test contrôlé montrant un gain du JSON sur une prose bien structurée (synthèse de recherche).

### Inferences
- Les modèles commerciaux ne « lisent » pas directement le prompt utilisateur : chez Veo (et sans doute ailleurs), un LLM le développe d'abord en description dense (caméra, transcription, SFX). Notre couche « réalisateur » doit donc faire ce travail elle-même, de manière déterministe et contrôlée, puis désactiver la réécriture du fournisseur quand c'est possible (`enhancePrompt=false`) pour éviter qu'un second LLM modifie les répliques françaises ou la mise en scène. L'effet de la désactivation sur la qualité est à mesurer (la doc prévient d'une baisse possible).
- Astuce pour apprendre le « style maison » du réécriveur Veo : envoyer des prompts courts (< 30 mots) pour récupérer le prompt réécrit dans la réponse, puis s'en servir comme gabarit (inférence tirée de la règle des 30 mots).
- Format conseillé pour un prompt par plan, compatible avec tous les moteurs : `[cadrage + mouvement caméra] [personnage nommé + signes visuels distinctifs] [action] [décor] [style constant de la série] / Dialogue: <Nom> dit d'un ton <x> : « réplique » / SFX: … / Ambient noise: … / (pas de texte à l'écran)`. Le JSON peut servir de représentation interne, puis être « rendu » en prose pour le modèle.
- Pour le français : Kling 3.0 Omni ne revendique pas le français en lip-sync (5 langues) et Veo est décrit comme centré sur l'anglais (voir section 2). La couche réalisateur doit donc prévoir un plan B : TTS français séparé, puis lip-sync en post-production.
- Sora ne doit plus être une cible d'intégration (API fermée), mais son guide reste utile pour la méthode (un mouvement, une action par plan ; dialogue calibré sur la durée).

### Gaps
- Pas de documentation publique trouvée sur un réécriveur de prompt chez Kling, Grok Imagine ou Sora : impossible de dire s'ils réécrivent le prompt, ni comment.
- Je n'ai pas pu lire le corps complet de la page Google sur le réécriveur. Défaut exact et possibilité de désactivation pour Veo 3.1 et Omni non confirmés.
- Pas de liste officielle des langues de dialogue supportées par Veo 3.1, Omni ou Grok Imagine. Le support du français n'est confirmé par aucune source officielle.
- Paramètre `negativePrompt` de Veo 3.1 non confirmé sur la page Gemini API lue. Le guide Vertex parle d'un prompt négatif, sans que j'aie pu vérifier le nom du champ pour 3.1.

## 2. Image→vidéo : quoi décrire quand une image de départ est fournie, keyframes première/dernière image, faire dialoguer des personnages sans confusion de lèvres

### Takeaway
Avec une image de départ, l'image fixe l'identité, la composition, la lumière et le style. Le texte doit décrire ce qui se passe ensuite (mouvement, caméra, évolution, audio), pas redécrire l'image. Les keyframes première/dernière image existent partout (Veo, Omni, Grok, Wan FLF2V), mais la transition entre les deux images est parfois peu naturelle. Contre la confusion de lèvres, toutes les sources convergent : nommer explicitement le locuteur avant chaque réplique, rendre les personnages visuellement et vocalement distincts, cadrer le locuteur (bouche visible), limiter chaque clip à un locuteur ou à des tours de parole très courts, et générer les réactions muettes dans des plans séparés.

### Cited Findings
**Ce qu'il faut décrire (ou non)**
- Veo : l'image d'entrée devient la première image, donc choisir celle qui ressemble le plus au début voulu. L'image peut venir d'un upload ou d'une génération précédente — [Gemini API, Veo](https://ai.google.dev/gemini-api/docs/veo).
- Sora 2 : l'image (`input_reference`) sert d'ancre de première image, et le texte décrit « what happens next ». L'image doit avoir la taille de la vidéo cible (JPEG, PNG ou WebP) — [OpenAI Cookbook](https://developers.openai.com/cookbook/examples/sora/sora2_prompting_guide).
- Kling 3.0 : traiter l'image comme une ancre qui préserve identité, mise en page et texte, et décrire comment la scène évolue (mouvement subtil, caméra, changement d'environnement) — [fal.ai](https://blog.fal.ai/kling-3-0-prompting-guide/).
- Runway (guides tiers) : l'image fixe sujets, composition, lumière et style, le texte gère l'animation ; redécrire l'image dans le prompt peut réduire le mouvement — [Atlabs](https://www.atlabs.ai/blog/how-to-prompt-with-runway-gen-4-image-to-video-a-comprehensive-guide). Ne pas répéter ce qui est visible, et n'ajouter du visuel que s'il change le mouvement (par exemple un élément absent de l'image) — [ImagineArt, Gen-4.5](https://www.imagine.art/blogs/runway-gen-4-5-prompt-guide). La page officielle Runway (help.runwayml.com) m'a renvoyé une erreur 403.

**Keyframes première/dernière image**
- Workflow officiel Veo 3.1 : générer une image de départ, puis une image de fin complémentaire (autre point de vue), toutes deux avec Gemini 2.5 Flash Image. Les fournir à « First and Last Frame » et décrire dans le prompt « the transition and the audio you want ». Exemple : « The camera performs a smooth 180-degree arc shot… The singer sings "…" » — [Google Cloud Blog](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1).
- Test indépendant de « Frames to Video » dans Flow : les vidéos commencent et finissent bien sur les images données, mais la transition n'est pas toujours naturelle — [DataCamp, Veo 3.1 guide](https://www.datacamp.com/tutorial/veo-3-1-complete-guide-with-examples).
- Omni Flash : interpolation première/dernière image — [Gemini API, Omni](https://ai.google.dev/gemini-api/docs/omni). Grok Imagine 1.5 : épinglage de la première image, de la dernière et d'images intermédiaires — [xAI Docs](https://docs.x.ai/docs/guides/video-generation). Wan2.1 FLF2V : extension du prompt par Qwen2.5-VL, prompts chinois recommandés — [GitHub Wan2.1](https://github.com/Wan-Video/Wan2.1).

**Faire parler deux à quatre personnages**
- Exemple officiel Google (« ingredients to video », avec références des personnages et du décor), en deux plans : plan 1, « create a medium shot of the detective behind his desk. He looks up at the woman and says in a weary voice, "Of all the offices in this town, you had to walk into mine." » ; plan 2, « create a shot focusing on the woman. A slight, mysterious smile plays on her lips as she replies, "You were highly recommended." ». C'est un champ/contrechamp avec **un locuteur par plan** — [Google Cloud Blog](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1).
- Sur deux personnes, Veo peut attribuer la réplique au mauvais personnage. Remède : ouvrir chaque réplique par l'identifiant du personnage (« The woman in the red jacket says… ») — [GlobalGPT (tiers)](https://www.glbgpt.com/hub/how-to-make-characters-speak-in-veo-3-1-the-ultimate-guide-to-dialogue-audio-lip-sync/). Si les deux personnages se ressemblent ou ont des voix proches, Veo « smears the dialogue across both mouths » ; il vaut mieux découper un long échange en clips courts — [veo3ai.io (tiers)](https://www.veo3ai.io/blog/veo-3-two-character-dialogue-guide-2026). Cadrer en plan moyen ou gros plan avec bouche visible, et décrire l'identité et la pose du locuteur — [Skywork (tiers)](https://skywork.ai/blog/how-to-prompt-lip-synced-dialogue-google-veo-3/).
- Kling : le dialogue non balisé peut être attribué au mauvais visage, surtout à partir de 3 personnages — [Morphic, Kling 3.0 guide (tiers)](https://morphic.com/resources/how-to/kling-3.0-guide). Voir aussi les règles fal (étiquettes uniques, action puis réplique, ton par personnage, « this is when the speaker switches ») et la liaison voix↔élément de Kling Omni (section 1).
- Sora 2 : un plan de 4 s tient une ou deux courtes répliques, un clip de 8 s un peu plus ; les longs discours se synchronisent mal. Pas plus de deux personnages (caméos) par génération — [OpenAI Cookbook](https://developers.openai.com/cookbook/examples/sora/sora2_prompting_guide).
- Workflow de sketch : verrouiller d'abord les images fixes des personnages, générer chaque plan en image→vidéo avec une action par plan, et ne mettre dialogue et lip-sync que sur les plans parlants — [anglr.co, AI comedy skit ads](https://anglr.co/examples/ai-comedy-skit-ads).
- Langue non anglaise : un développeur a obtenu de la parole en russe en écrivant le prompt en anglais et les répliques entre guillemets dans la langue cible (pré-Veo 3.1, sans mesure de qualité) — synthèse de recherche sur un post LinkedIn ; un revendeur décrit Veo 3.1 comme « English-centric », avec un lip-sync multilingue moins explicite que Kling 3.0 — [Atlas Cloud (revendeur concurrent)](https://www.atlascloud.ai/blog/guides/ai-video-models-native-audio-compared). Un test d'utilisateur indique que Veo 3.1 (octobre 2025) a réduit la dérive de synchro labiale et gère les tours de parole — [Eastondev (FR, 12/2025)](https://eastondev.com/blog/fr/posts/ai/20251207-veo3-audio-generation-guide/).

### Inferences
- Pour nos personnages cartoon, la couche réalisateur devrait produire **une image de départ par plan** (rendu du personnage dans la pose et le cadrage du plan, à partir des planches de référence). Le prompt vidéo ne décrirait alors que le mouvement, la caméra, l'émotion, la réplique et le son, plus un rappel court de l'identité (nom + 1–2 signes distinctifs) pour l'attribution de parole.
- Règle de découpage dialogue : un plan = un locuteur (champ/contrechamp), une à deux répliques courtes par tranche d'environ 4 s. Les réactions muettes des autres personnages vont dans des plans séparés, avec un prompt « No dialogue » explicite (formulation Omni).
- Les personnages doivent être conçus distincts par la silhouette, la couleur et le timbre de voix (voix liées via Kling Element Voice, références de voix Grok ou TTS séparé). C'est la principale défense contre la confusion de lèvres à 3–4 personnages.
- Chute finale « visage choqué face caméra » : le plus fiable est de générer la dernière image (gros plan choqué regard caméra) et de l'imposer comme `lastFrame` (Veo, Omni, Grok), puis de figer cette image au montage.

### Gaps
- Pas de mesure publiée du taux d'erreur d'attribution de parole selon le nombre de personnages, ni d'étude sur le lip-sync en français (et encore moins en français ivoirien) pour Veo, Kling, Grok ou Omni.
- Le guide officiel image→vidéo de Kling et celui de Runway n'ont pas pu être lus directement.

## 3. Multi-plans et vidéo longue : fonctions produits et méthodes de recherche

### Takeaway
En octobre 2026, les produits proposent tous du multi-plans « en une génération » dans une fenêtre d'environ 8–15 s : Kling 3.0 Director Mode (≤ 6 plans, 15 s), Veo 3.1 en timestamp prompting (plans de 2 s dans 8 s), Omni Flash (multi-plans par défaut), Wan 2.6 (`shot_type: "multi"`). Au-delà, on chaîne par extension depuis la dernière image (Veo ≤ 148 s, Omni ≤ 40 s, Grok) et par références partagées (ingredients, éléments, références). La recherche est passée de pipelines « keyframes + I2V par plan » à la génération holistique de scène (LCT, HoloCine : tous les plans en une passe, avec attention partagée), aux modèles autorégressifs ou en streaming (MAGI-1, SkyReels-V2, FramePack, Self Forcing, ShotStream) et à des agents LLM qui planifient, génèrent, évaluent et régénèrent (MovieAgent, AniMaker, MVAgent). Les benchmarks 2026 montrent que la cohérence chute quand l'écart entre deux apparitions d'un personnage grandit, et qu'une mémoire explicite par entité aide le plus.

### Cited Findings
**Produits**
- **Kling 3.0 Director Mode** : un mode automatique (le modèle choisit les coupes) et un mode personnalisé (contenu par plan, durée par plan dans un total de 15 s, angle et cadrage, timing des coupes) — [kling.ai blog, Director Mode](https://kling.ai/blog/kling-video-3-director-mode-multi-shot-tutorial) (contenu obtenu via le résumé de recherche ; la page n'a pas rendu son corps). Storyboards de jusqu'à 6 plans par sortie, durée ≤ 15 s — [fal.ai](https://blog.fal.ai/kling-3-0-prompting-guide/). Une source tierce parle de « 3 à 15 s par plan », ce qui est incompatible avec un total de 15 s. Kling 3.0 aurait été lancé le 4/02/2026 (source tierce) — [Morphic glossary](https://morphic.com/es/ai-glossary/Kling-30). Convention communautaire : 3–6 plans pour 10–15 s, soit environ 1,5–4 s par plan — [AIToolCurator](https://www.aitoolcurator.com/learn/kling-guide/cinematic-video-prompting/) ; en-têtes « Shot N (0-4s) » — [Atlabs](https://www.atlabs.ai/blog/kling-3-prompt-examples-templates).
- **Veo 3.1 / Flow** : timestamp prompting officiel, c'est-à-dire plusieurs plans dans une génération de 8 s, par exemple « [00:00-00:02] Medium shot from behind… [00:02-00:04] Reverse shot of the explorer's freckled face… SFX: … [00:04-00:06] Tracking shot… [00:06-00:08] Wide, high-angle crane shot… ». Google le présente comme un moyen de garantir la cohérence visuelle — [Google Cloud Blog](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1). Flow (15/10/2025) : audio ajouté à « Ingredients to Video », « Frames to Video » et « Extend », fonctions qualifiées d'expérimentales — [Google blog, Veo 3.1 & Flow](https://blog.google/technology/ai/veo-updates-flow/). Dans Flow, l'extension se fait depuis le scene builder, via « + » puis « Extend », et ne s'applique qu'aux clips générés par Veo 3.1 dans Flow — [DataCamp](https://www.datacamp.com/tutorial/veo-3-1-complete-guide-with-examples).
- **Gemini Omni Flash** : multi-plans par défaut, timecodes « [0-3s] », extension jusqu'à 40 s, édition multi-tours (`previous_interaction_id`) qui conserve ce qui n'est pas mentionné — [Gemini API, Omni](https://ai.google.dev/gemini-api/docs/omni).
- **Sora 2** (fermé le 24/09/2026) : extensions de ≤ 20 s, 6 fois, jusqu'à 120 s au total, avec le clip complet comme contexte ; personnages uploadés (MP4 de 2–4 s) appelés par nom et ID — [OpenAI Cookbook](https://developers.openai.com/cookbook/examples/sora/sora2_prompting_guide).
- **Grok Imagine** : extension depuis la dernière image, avec original et extension fusionnés ; référence→vidéo avec épinglage d'images — [xAI Docs](https://docs.x.ai/docs/guides/video-generation).
- **LTX Studio** : le Storyboard Generator découpe un script en scènes et plans, et extrait personnages et objets sous forme d'« Elements » réutilisables (images FLUX ou Nano Banana, ratio fixé pour tous les plans) — [LTX blog](https://website.ltx.studio/blog/ltx-storyboard-generator-update). LTX sépare les Elements réutilisables de la direction par plan, mais « consistent characters » n'est pas prouvé sur une séquence de 6 plans révisée — [DIYAI (comparatif indépendant)](https://diyai.io/ai-tools/video-generation/ai-storyboard-generator/). Un guide Lightricks décrit aussi des identités IC-LoRA par personnage, appelées par nom — [ltx.io](https://ltx.io/blog/how-to-build-a-complete-pre-visualization-pipeline).

**Recherche : génération holistique de scène**
- **LCT – Long Context Tuning** (CUHK / ByteDance Seed, arXiv 2503.10589, mars 2025, ICCV 2025) : étend la fenêtre de contexte d'un modèle mono-plan à toute la scène (attention complète sur tous les plans, positions 3D entrelacées, bruit asynchrone). Il permet la génération conjointe ou autorégressive des plans (KV-cache après fine-tuning causal) et l'extension interactive. Les auteurs critiquent les pipelines par keyframes : générer chaque plan indépendamment ne garantit pas la cohérence, et un personnage entrant entre deux keyframes peut échapper au conditionnement — [arXiv 2503.10589](https://arxiv.org/abs/2503.10589).
- **HoloCine** (HKUST / Ant Group, arXiv 2510.20822, octobre 2025) : base Wan2.2 14B. Prompt hiérarchique = prompt global (personnages, décor, intrigue) + prompts par plan séparés par **`[shot cut]`**, avec balises `[character1]` et termes de plan comme `[Long shot]`. Window Cross-Attention : chaque plan n'attend que le prompt global et son propre prompt. Sparse Inter-Shot Self-Attention : dense dans le plan, résumés entre plans, pour un coût quasi linéaire. Paliers de 5, 15 et 60 s, jusqu'à 13 plans à 480×832. Données : environ 400k échantillons multi-plans issus de films et séries, légendés par Gemini 2.5 Flash. Score de contrôle des transitions de 0,9837, contre 0,5370 pour CineTrans et 0,4843 pour Wan2.2 ; cohérence inter-plans de 0,7509, contre 0,7364 pour StoryDiffusion+Wan2.2. Limite : raisonnement causal faible (un verre reste vide après qu'on y verse de l'eau). Kling 2.5 Turbo et Vidu produisaient un seul plan continu dans leurs tests — [arXiv HTML](https://arxiv.org/html/2510.20822v1).
- Code HoloCine : entrée structurée `global_caption`, `shot_captions[]`, `num_frames` (241 ≈ 15 s ; 81 ≈ 5 s pour peu de VRAM) et `shot_cut_frames` optionnel (ex. `[37, 73, 113, 169, 205]`). Le texte est tronqué à 512 tokens (T5). Checkpoints HoloCine-14B-full et -sparse publiés. Annoncés ou prévus : versions > 1 min, une version 5B, l'entrée première image / keyframes et « HoloCine-audio » — [GitHub HoloCine](https://github.com/yihao-meng/HoloCine).
- **Captain Cinema** (arXiv 2507.18634, juillet 2025, JHU / ByteDance Seed / Stanford / CUHK) : planification descendante de keyframes pour toute l'histoire, puis synthèse du mouvement entre keyframes ; entraînement entrelacé de MM-DiT pour des contextes longs — [arXiv](https://arxiv.org/html/2507.18634v1).

**Recherche : autorégressif, streaming, longueur infinie**
- **MAGI-1** (Sand AI, arXiv 2505.13211) : génération par chunks de 24 images (1 s à 24 fps) avec masque d'attention block-causal. Jusqu'à 4 chunks en parallèle ; le chunk suivant démarre quand le courant atteint un certain niveau de débruitage (streaming temps réel). 24 B paramètres ; coût d'inférence de pointe constant quelle que soit la longueur ; open-source — [arXiv](https://arxiv.org/pdf/2505.13211) ; [GitHub](https://github.com/SandAI-org/MAGI-1).
- **SkyReels-V2** (Skywork, arXiv 2504.13074) : « Diffusion Forcing » avec un niveau de bruit indépendant par token, qui permet l'extension ouverte façon autorégressive ; MLLM, pré-entraînement multi-étapes et RL — [arXiv](https://arxiv.org/pdf/2504.13074).
- **FramePack** (Stanford, NeurIPS 2025) : compresse l'historique selon l'importance des images pour tenir dans un contexte fixe, avec des mesures anti-dérive (extrémités établies tôt, ordre d'échantillonnage ajusté) — [arXiv 2504.12626](https://arxiv.org/pdf/2504.12626). **Self Forcing** (Adobe / UT Austin, NeurIPS 2025) : l'entraînement se fait sur les propres sorties du modèle (KV-cache), avec une perte au niveau vidéo et un cache roulant, pour du streaming temps réel sur un GPU — [arXiv 2506.08009](https://arxiv.org/pdf/2506.08009v1.pdf).
- 2026 (résumés seuls) : **ShotStream** (arXiv 2603.25746) fait de la prédiction « plan suivant » causale, conditionnée sur l'historique, à environ 16 FPS sur un GPU — [arXiv](https://arxiv.org/html/2603.25746v1). **FilmWeaver** (2512.11274) utilise un cache de plans pour la mémoire long terme et un cache temporel intra-plan — [arXiv](https://arxiv.org/pdf/2512.11274). **STAGE** (2512.12372) prédit une paire image de début / image de fin par plan, avec une mémoire multi-plans — [arXiv](https://arxiv.org/html/2512.12372v2). **InfinityStory** (2603.03646) traite la cohérence de monde et les transitions sensibles aux personnages — [arXiv](https://arxiv.org/html/2603.03646).
- Benchmarks 2026 (résumés seuls) : **EntityBench** (2605.15199) compte 140 épisodes ; la cohérence inter-plans chute quand l'écart entre apparitions grandit, et une mémoire explicite par entité (EntityMem) donne la meilleure fidélité de personnage — [arXiv](https://arxiv.org/abs/2605.15199). **PersonaShot** (2608.16717) réunit environ 1 000 segments et 16 métriques, et vérifie aussi la continuité physique et émotionnelle des personnages — [arXiv](https://arxiv.org/abs/2608.16717). **MSVBench** (2602.23969) — [arXiv](https://arxiv.org/html/2602.23969v1).

**Recherche : pipelines multi-agents histoire→vidéo**
- **MovieAgent** (NUS Show Lab, arXiv 2503.07314) : agents réalisateur, scénariste, storyboarder et repéreur, en CoT hiérarchique ; entrée = script + banque de personnages ; sans entraînement. LLM GPT-4o, images ROICtrl (ED-LoRA), vidéo SVD / HunyuanVideo-I2V — [arXiv](https://arxiv.org/html/2503.07314v1) ; [GitHub](https://github.com/showlab/MovieAgent).
- **AniMaker** (arXiv 2506.10540, juin 2025) : agents Director (storyboard), Photography, Reviewer et Post-Production (montage + voix off). MCTS-Gen explore plusieurs candidats par clip sous budget, et AniEval note chaque clip dans le contexte des clips voisins. Les auteurs revendiquent +14,6 % sur AniEval — [arXiv](https://arxiv.org/html/2506.10540v2).
- **StoryAgent** (2411.04925) : agents histoire, storyboard, vidéo, coordination et évaluation, plus LoRA-BE pour l'I2V à protagoniste constant. Les auteurs jugent Mora insuffisant sur ce point — [arXiv](https://arxiv.org/html/2411.04925v1). **Mora** (2403.13248) : multi-agent généraliste (T2V, I2V, édition) — [arXiv](https://arxiv.org/html/2403.13248v3). **FilmAgent** (2501.12909) : production dans des espaces 3D virtuels, évaluée sur la fidélité au thème, la caméra, l'adéquation script/acteurs et la cohérence de l'intrigue — [arXiv](https://arxiv.org/pdf/2501.12909). **DreamFactory** (2408.11788, août 2024) : multi-agent avec itération sur keyframes et CoT ; métriques Cross-Scene Face Distance et Style Consistency — [arXiv](https://arxiv.org/html/2408.11788v1). **MAViS** (2508.08487) décrit DreamFactory comme un pipeline script→scène→plan et reproche à ces méthodes beaucoup de travail manuel (script, LoRA par personnage) — [arXiv](https://arxiv.org/html/2508.08487v4). **MVAgent** (2609.30609, résumé seul) : construction de conditions cohérentes par plan et RL par plan, meilleure cohérence inter-plans sur ViMax-Bench — [arXiv](https://arxiv.org/abs/2609.30609).

### Inferences
- Pour 25–60 s, le schéma le plus réaliste avec des API commerciales est hybride. On prévoit 3–6 « blocs » de 8–15 s, chacun généré en multi-plans natif (Kling Director Mode, timestamps Veo, Omni) à partir d'images de référence communes aux blocs : ingredients Veo, éléments Kling, références Grok. Les blocs sont raccordés soit par coupe franche (la plus naturelle en comédie), soit par extension « dernière image → suite » quand la continuité d'action l'exige.
- Les résultats LCT, HoloCine et EntityBench justifient une **mémoire explicite par personnage** dans notre couche : feuille de référence, voix, tenue et accessoires, réinjectée à chaque plan. Il ne faut pas compter sur la chaîne dernière image → première image, qui propage la dérive.
- La boucle « générer N candidats → noter avec un VLM → garder le meilleur » (AniMaker MCTS-Gen, Reviewer) est directement transposable. Comme les guides insistent sur la variabilité d'un tirage à l'autre (« The same prompt can produce different results on each run », cookbook Sora), le tri automatique fait partie intégrante du moteur.
- HoloCine (open-source, base Wan2.2) est la meilleure piste pour un moteur « maison » multi-plans. Mais l'entrée par keyframes et l'audio ne sont pas encore publiés, et la résolution est de 480×832 : il faudrait ajouter TTS français et lip-sync en post-production.

### Gaps
- Chiffres officiels Kling Director Mode (durée min/max par plan, comportement audio entre plans) non confirmés sur une page Kling lisible ; seuls le résumé de recherche et fal sont disponibles.
- Papiers 2026 (ShotStream, EntityBench, PersonaShot, MVAgent, STAGE, FilmWeaver, InfinityStory) lus seulement en résumé. Code et licences non vérifiés.
- Sorties du code de Captain Cinema et de DreamFactory non confirmées.

## 4. Timing comique : beats, plans de réaction, pauses, freeze frames, coupes sur le dialogue

### Takeaway
Les guides de créateurs disent la même chose : le timing comique d'un sketch IA se fait **au montage**, pas dans le générateur. On génère des clips un peu plus longs, une action par plan, puis on coupe les temps morts, on laisse un silence avant la chute, on tient le plan de réaction plus longtemps que « naturel », et on termine par un zoom ou un freeze sur le visage choqué, souvent avec un effet sonore (record scratch). Il n'existe aucune donnée rigoureuse sur les durées exactes à tenir.

### Cited Findings
- Les clips générés paraissent souvent plats. Le remède est de générer des clips plus longs et de couper pauses et réactions au montage, car le timing comique vient surtout du montage. Il faut aussi tenir le plan de réaction gagnant « a beat longer than feels natural », laisser un silence avant la chute et ajouter un room tone et quelques effets — [anglr.co](https://anglr.co/examples/ai-comedy-skit-ads).
- Dans le prompt d'une réaction, préciser le regard (eyeline), le changement émotionnel et la pause avant la réaction — [Revid.ai](https://www.revid.ai/blog/funny-ai-videos).
- Le contenu divertissement et comédie court coupe souvent toutes les 2–4 s. Un éditeur conseille de supprimer les temps morts de plus de 0,3 s, seuil qui vient d'un blog d'éditeur et non d'une règle de plateforme — [Sozee](https://www.sozee.ai/resources/edit-tiktok-trend-videos-retention/).
- Freeze sur l'expression la plus drôle pour laisser le spectateur absorber la blague, éventuellement avec une légende qui fait seconde chute — [Finchley Learning](https://www.finchley.co.uk/finchley-learning/the-art-of-timing-in-comedy-video-production). Zoom sur un visage choqué et record scratch avant le freeze pour souligner l'absurde — [Finchley Learning](https://finchley.co.uk/finchley-learning/funny-video-editing-techniques-to-make-your-content-stand-out).
- Les monteurs comiques figent l'image sur des réactions absurdes ou surprises pour étirer un beat ; garder ou non l'audio pendant le freeze est un choix créatif qui change l'effet — [Morphic glossary, Freeze Frame](https://morphic.com/es/ai-glossary/Freeze-Frame).
- Méthode « [cut] » pour enchaîner des scènes en un prompt Veo 3.1 (pubs UGC TikTok), une scène par bloc — [VO3 AI blog, 26/06/2026](https://www.vo3ai.com/blog/tiktok-ugc-ads-in-vo3-ai-multi-scene-workflow-inspired-by-twitters-cut-prompt-ti-2026-06-26).
- Des créateurs TikTok de sketchs Veo 3 assemblent « nothing but prompts and a bit of iMovie » — [TikTok discover, Veo 3 Prompt Theory comedy](https://www.tiktok.com/discover/made-with-google-veo-3-prompt-theory-comedy).
- Allégations non vérifiées à écarter : un outil prétend « +234 % de rires » grâce au timing optimisé par IA — [Hooked (affirmation marketing)](https://www.hooked.so/tools/ai-comedy-skit-generator).
- Rappel méthodologique Sora : décrire les actions en beats chronométrés (pas, pauses) ; deux clips de 4 s montés peuvent mieux marcher qu'un clip de 8 s — [OpenAI Cookbook](https://developers.openai.com/cookbook/examples/sora/sora2_prompting_guide).

### Inferences
- Gabarit de rythme pour 25–60 s (à valider par A/B test). Accroche de 0–3 s : situation absurde ou réplique choc dès la 1re image. Escalade en plans de 2–4 s, en champ/contrechamp sur le dialogue. Twist avec un plan de réaction muet tenu un peu plus longtemps. Silence court (environ 0,3–0,5 s), puis chute : gros plan visage choqué regard caméra, zoom rapide, record scratch, freeze de 1–2 s (durées à tester, aucune source chiffrée).
- La couche réalisateur doit sortir **deux artefacts** : la liste de plans à générer, avec des marges de 0,5–1 s avant et après l'action utile, et une **EDL ou timeline de montage** (points d'entrée/sortie, freeze, zooms, SFX, sous-titres incrustés en post). Le générateur ne doit jamais incruster de texte.
- Générer les plans de réaction séparément, sans dialogue et avec un regard précis, donne un matériau de coupe réutilisable. Une banque de réactions par personnage (choc, gêne, fou rire) peut se recycler entre sketchs.

### Gaps
- Aucune étude rigoureuse (académique ou plateforme TikTok) sur les durées optimales de freeze, de pause avant la chute ou de rythme de coupe pour la comédie courte.
- Pas de source sur la façon dont des créateurs africains ou francophones de sketchs IA montent leurs vidéos.

## 5. Format de représentation intermédiaire (shot list) utilisé par les pipelines

### Takeaway
Tous les pipelines sérieux passent par une représentation hiérarchique **histoire → scènes → plans**, avec une banque de personnages séparée (images + voix). Chaque plan porte au minimum : personnages présents, action ou beat d'intrigue, type de plan et mouvement caméra, réplique, et parfois durée ou instants de coupe. Côté modèles, cette représentation est « rendue » soit en prompt global + prompts par plan séparés par `[shot cut]` (HoloCine), soit en blocs horodatés `[00:00-00:02]` (Veo, Omni), soit en « Shot N (durée) » (Kling), soit en prose + « Cinematography / Actions / Dialogue » (Sora). Les paramètres techniques (durée, format, résolution) restent hors prose.

### Cited Findings
- MovieAgent : le Shot Plan Agent découpe chaque scène en plans, et chaque plan enregistre « characters involved, plot beat, camera movements, shot type, subtitles ». L'agent raisonne sur le cadrage, la technique caméra, la continuité visuelle entre plans et l'alignement narratif — [arXiv 2503.07314](https://arxiv.org/html/2503.07314v1). La banque de personnages est un dossier `character_list/<nom>/photo_1.jpg, photo_2.jpg, audio.wav`, avec un `script_synopsis.json` en entrée ; le README ne publie pas de schéma JSON de plan — [GitHub MovieAgent](https://github.com/showlab/MovieAgent).
- HoloCine : `global_caption` (qui se termine par exemple par « This scene contains 5 shots. »), `shot_captions[]`, `num_frames`, `shot_cut_frames[]` alignés sur l'ordre des plans, avec des balises `[character1]`/`[character2]`. Forme brute : « [global caption] … [per shot caption] … [shot cut] … ». Limite de 512 tokens — [GitHub HoloCine](https://github.com/yihao-meng/HoloCine).
- Veo 3.1 : blocs `[00:00-00:02] <cadrage> <sujet> <action>. SFX: … Emotion: …` — [Google Cloud Blog](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1). Omni : timecodes « [0-3s] » ou langage naturel, et `task` explicite — [Gemini API, Omni](https://ai.google.dev/gemini-api/docs/omni).
- Kling 3.0 : ligne maîtresse, puis lignes « Multi shot Prompt N: … (Duration: 5 seconds) » ; sujets définis en tête avec des descriptions identiques d'un plan à l'autre — [fal.ai](https://blog.fal.ai/kling-3-0-prompting-guide/). En-têtes « Shot N » + « (0-4s) » + descriptions de personnages entre crochets — [Atlabs (tiers)](https://www.atlabs.ai/blog/kling-3-prompt-examples-templates).
- Sora 2 : gabarit prose + « Cinematography: » + « Actions: » + « Dialogue: ». Modèle, taille, durée et IDs de personnages passent en paramètres d'API, jamais dans la prose ; un bloc par plan avec une configuration caméra, une action et une recette de lumière — [OpenAI Cookbook](https://developers.openai.com/cookbook/examples/sora/sora2_prompting_guide).
- LTX Studio sépare les Elements réutilisables (personnages, lieux, objets) de la direction par plan — [DIYAI](https://diyai.io/ai-tools/video-generation/ai-storyboard-generator/) ; [LTX blog](https://website.ltx.studio/blog/ltx-storyboard-generator-update).
- AniMaker : le Director produit des storyboards, le Reviewer note chaque clip dans le contexte des clips voisins (cohérence de l'histoire, achèvement de l'action) et le Post-Production gère montage et voix off — [arXiv 2506.10540](https://arxiv.org/html/2506.10540v2). FilmAgent évalue la fidélité du script, la pertinence des réglages caméra, l'adéquation script/profils d'acteurs, la justesse des actions et la cohérence de l'intrigue — [arXiv 2501.12909](https://arxiv.org/pdf/2501.12909).
- STAGE prédit une paire image de début / image de fin par plan dans un storyboard (résumé seul) — [arXiv 2512.12372](https://arxiv.org/html/2512.12372v2). EntityBench suit personnages, objets et lieux par plan (résumé seul) — [arXiv 2605.15199](https://arxiv.org/abs/2605.15199).
- Prompting JSON chez les créateurs : champs caméra, lumière, environnement et audio, présentés comme une « shot list » — [Artlist](https://artlist.io/blog/veo-3-json-prompts/).

### Inferences
- Schéma proposé pour notre couche réalisateur, synthèse des formats ci-dessus (inférence, non tiré d'une source unique) :
  - `sketch` : `{id, titre, durée_cible_s (25–60), format "9:16", langue "fr-CI", structure: [hook, escalade, twist, chute], style_global (palette 3–5 couleurs, rendu cartoon), lieux[], personnages[]}`
  - `personnage` (banque persistante, mémoire par entité) : `{id, nom, description_canonique (1–2 phrases identiques partout), signes_distinctifs, images_ref[], planche_poses[], voix {tts_voice_id | clip_ref}, tics_de_jeu}`
  - `plan` : `{n, beat (hook|escalade|twist|chute), durée_s, personnages_visibles[], locuteur (0 ou 1), cadrage (GP/PM/PA/plan large), angle, mouvement_caméra (un seul), action (une seule, en beats chronométrés), émotion/regard, réplique {texte_fr, ton}, sfx[], ambiance, image_début (ref ou à générer), image_fin optionnelle (ex. visage choqué face caméra), refs[], négatifs/contraintes ("No dialogue", pas de texte à l'écran), moteur_cible, bloc (pour regrouper en multi-plans natif)}`
  - `montage` : `{plan_n, in_s, out_s, transition (cut), effets (zoom, freeze_s, record_scratch), sous-titres_post}`
- Un « renderer » par moteur convertit le même plan en syntaxe native : timestamps pour Veo et Omni, « Shot N (durée) » pour Kling, `[shot cut]` pour HoloCine, `<IMAGE_N>` ou références pour Grok. On garde ainsi une seule source de vérité et des adaptateurs.

### Gaps
- Aucun schéma JSON de plan publié tel quel par MovieAgent, AniMaker ou les produits commerciaux. Le schéma ci-dessus est une synthèse et non une norme.
- Pas de format standard de l'industrie (type EDL ou OTIO) documenté dans ces pipelines IA pour transmettre les décisions de montage comique.
