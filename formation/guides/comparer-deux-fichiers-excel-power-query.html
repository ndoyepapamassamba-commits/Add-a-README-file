Comparer deux fichiers Excel avec Power Query

Quelles lignes ont été ajoutées, supprimées ou modifiées entre deux extractions ? Trois jointures répondent aux trois questions, sans RECHERCHEV. Exemple complet sur deux arrêtés de portefeuille fictifs, code M, pont d'encours qui se termine par un contrôle à zéro, puis les différences en couleur.

Mis à jour le 22/10/2026 · Données d'exemple 100 % fictives · Excel 2016 ou plus récent, ou Microsoft 365, sous Windows

La réponse en 4 étapes :

  1. Chargez les deux fichiers dans Power Query, en connexion uniquement. Nettoyez la clé (ici le numéro de contrat) : type Texte, Supprimer les espaces, MAJUSCULES. Vérifiez qu'elle n'est pas en double.
  2. Accueil › Combiner › Fusionner les requêtes, clé sélectionnée des deux côtés, type de jointure Anti gauche : ancien fichier en haut, vous obtenez les lignes supprimées ; nouveau fichier en haut, les lignes ajoutées.
  3. Type Interne : les lignes présentes des deux côtés. Développez l'ancien montant, calculez une colonne Écart et gardez les écarts au-delà d'une tolérance : ce sont les lignes modifiées.
  4. Bouclez par un pont : ancien total − supprimées + ajoutées ± écarts = nouveau total. La ligne de contrôle doit valoir 0.

Sur l'exemple fictif de ce guide : 2 prêts sortis, 2 nouveaux, 10 encours modifiés, et un contrôle à 0.

Le principe : une clé, trois questions, trois jointures

Le service reporting de la Banque Fictive de l'Ouest (BFO), une banque imaginaire, reçoit chaque fin de mois une extraction de son portefeuille de prêts : une ligne par prêt, avec son numéro de contrat et son encours. Entre fin août et fin septembre 2026, l'encours total a augmenté. Le responsable veut savoir pourquoi, prêt par prêt. Il faut répondre à trois questions :

  • Quels prêts sont sortis ? Ils étaient dans le fichier d'août et ne sont plus dans celui de septembre.
  • Quels prêts sont nouveaux ? Ils sont dans septembre et n'étaient pas dans août.
  • Quels prêts ont changé ? Ils sont dans les deux fichiers, avec un encours différent.

Pour rapprocher deux lignes, il faut une clé : une colonne (ou un groupe de colonnes) qui identifie chaque ligne sans ambiguïté et qui ne change pas d'un fichier à l'autre. Ici, le numéro de contrat. Le nom du client ne convient pas : un client peut avoir plusieurs prêts, et son nom peut être saisi de deux façons.

Dans Power Query, rapprocher deux tables par une clé s'appelle fusionner des requêtes. Microsoft le résume ainsi : « Une opération de requête de fusion joint deux tables existantes en fonction des valeurs correspondantes d'une ou plusieurs colonnes. » Le type de jointure choisi décide des lignes gardées. Chacune des trois questions a la sienne.

La vue d'ensemble de Microsoft Learn décrit six types de jointure (la page du support Microsoft sur Excel cite en plus une jointure croisée, qui ne sert pas ici). Les libellés ci-dessous sont ceux de la documentation Microsoft en français, avec le nom qu'ils prennent dans le code M :

Les six types de jointure décrits par Microsoft Learn (table de gauche = celle du haut dans la boîte de dialogue)
Type de jointureLignes renvoyées (d'après la doc Microsoft)En code MPour comparer deux fichiers

Les noms varient selon les pages et les versions : la vue d'ensemble de Microsoft Learn écrit « Anti jointure gauche », ses pas à pas font choisir « Anti gauche », et la page du support Microsoft appelle la jointure externe complète « Externe entière ». Dans des tutoriels en français, vous croiserez aussi « gauche opposée » : c'est la même opération. Dans la boîte de dialogue, chaque type est suivi d'un court rappel entre parenthèses (en anglais, par exemple, « Left Anti (rows only in first) »), dont la traduction peut changer d'une version à l'autre. En cas de doute, ouvrez Accueil › Éditeur avancé : le nom JoinKind du code M, lui, ne change pas.

La place des tables compte. Microsoft le souligne : « La position (gauche ou droite) des tables devient très importante lorsque vous sélectionnez le type de jointure approprié à utiliser. » La table de gauche est celle que vous choisissez en haut de la boîte de dialogue Fusionner.

Étape 0 — Préparer les deux tables

C'est l'étape qui décide de la justesse de tout le reste. Trois choses à faire : charger les deux tableaux sans les afficher, nettoyer la clé, vérifier qu'elle est unique.

Charger les deux tableaux en connexion uniquement

  1. Ouvrez un classeur vierge : ce sera votre classeur de comparaison. Enregistrez-le en dehors du dossier des deux fichiers.
  2. Données › Obtenir des données › À partir d'un fichier › À partir d'un classeur Excel (Excel 2016 : Données › Nouvelle requête › À partir d'un fichier › À partir d'un classeur). Choisissez portefeuille-2026-08.xlsx, puis Importer.
  3. Dans le Navigateur, sélectionnez le tableau T_Portefeuille (icône de tableau), pas la feuille Portefeuille, puis Transformer les données.
  4. À droite, dans Paramètres de requête › Propriétés › Nom, nommez la requête Aout, sans accent : ce nom sera repris tel quel dans le code M des étapes suivantes.
  5. Vérifiez les types avec l'icône à gauche de chaque en-tête : Arrêté en Date ; Contrat, Client, Agence et Produit en Texte ; Encours en Nombre décimal.

Le type de la clé n'est pas un détail. Microsoft Learn prévient que les colonnes de jointure « doivent être du même type de données, sinon l'opération de fusion risque de ne pas générer de résultats corrects ». Un numéro de contrat se garde en Texte dans les deux requêtes : c'est un identifiant, pas une quantité, et il peut commencer par des zéros.

Nettoyer la clé : espaces et majuscules

  1. Sélectionnez la colonne Contrat, puis Transformer › Format › Supprimer les espaces. La fonction M correspondante, Text.Trim, retire les espaces au début et à la fin du texte : « Par défaut, tous les espaces blancs de début et de fin sont supprimés. »
  2. Toujours sur Contrat : Transformer › Format › MAJUSCULES (Text.Upper). Power Query distingue les majuscules des minuscules (Microsoft écrit : « Power Query respecte la casse ») : « bfo-1005 » et « BFO-1005 » ne se rapprocheraient pas.
  3. Accueil › Fermer et charger › Fermer et charger dans…, choisissez Créer uniquement la connexion, puis OK. La requête existe, sans remplir de feuille : elle ne sert que d'entrée aux comparaisons.

Dans l'Éditeur avancé (Accueil › Éditeur avancé), la requête ressemble à ceci. Les deux étapes de nettoyage y sont réunies en une :

// Requête Aout : le portefeuille de fin août, clé nettoyée
let
    Source = Excel.Workbook(File.Contents("C:\Reporting\Comparaison\portefeuille-2026-08.xlsx"), null, true),
    Portefeuille = Source{[Item = "T_Portefeuille", Kind = "Table"]}[Data],
    Types = Table.TransformColumnTypes(Portefeuille, {
        {"Arrêté", type date}, {"Contrat", type text}, {"Client", type text},
        {"Agence", type text}, {"Produit", type text}, {"Encours", type number}}),
    // Supprimer les espaces de début et de fin, puis MAJUSCULES
    CleNettoyee = Table.TransformColumns(Types, {{"Contrat", each Text.Upper(Text.Trim(_)), type text}})
in
    CleNettoyee

Pour le fichier de septembre, le plus sûr est de dupliquer cette requête : rouvrez l'éditeur (Données › Requêtes et connexions, puis double-clic sur Aout), clic droit sur Aout dans le volet Requêtes › Dupliquer, nommez la copie Septembre, cliquez sur l'étape Source et remplacez 2026-08 par 2026-09 dans la barre de formule. Les deux requêtes ont ainsi exactement les mêmes étapes ; vérifiez que Septembre est, elle aussi, en connexion uniquement. Si Excel l'a chargée dans une feuille : Données › Requêtes et connexions, clic droit sur Septembre › Charger dans… › Créer uniquement la connexion. Ce même chemin sert pour toutes les requêtes de ce guide.

  • Aout : 15 lignes, 6 colonnes, somme de Encours 184 755 000,40.
  • Septembre : 16 lignes à ce stade (le doublon est encore là), somme 193 415 000. La clé de BFO-1005 n'a plus d'espace.

Sans ce nettoyage, « BFO-1005␣ » et « BFO-1005 » seraient deux clés différentes : le prêt apparaîtrait à la fois parmi les prêts sortis (12 300 000) et parmi les nouveaux (11 900 000), et sa vraie variation, −400 000, disparaîtrait.

Vérifier que la clé est unique

Une jointure associe chaque ligne de gauche à toutes les lignes de droite qui ont la même clé. Si un contrat figure deux fois dans un fichier, il sort deux fois du rapprochement : les lignes se multiplient, les totaux gonflent, sans aucun message d'erreur. D'où une requête de contrôle :

  1. Dans le volet Requêtes, clic droit sur Septembre › Référence. Nommez la nouvelle requête Doublons_Septembre.
  2. Accueil › Regrouper par : regroupez par Contrat, nom de la nouvelle colonne Nombre de lignes, opération Compter les lignes. OK.
  3. Flèche de l'en-tête Nombre de lignes › Filtres numériques › Supérieur à…, saisissez 1, puis OK.
// Requête Doublons_Septembre : les contrats présents plus d'une fois (résultat attendu en régime normal : aucune ligne)
let
    Source = Septembre,
    ParContrat = Table.Group(Source, {"Contrat"}, {{"Nombre de lignes", each Table.RowCount(_), Int64.Type}}),
    Doublons = Table.SelectRows(ParContrat, each [Nombre de lignes] > 1)
in
    Doublons
  • Une seule ligne : Contrat BFO-1008, Nombre de lignes 2.
  • Le même contrôle fait sur Aout (une requête Doublons_Aout, construite de la même façon) ne renvoie aucune ligne.

Pour voir les deux lignes en entier, faites une autre référence de Septembre, sélectionnez Contrat, puis Accueil › Conserver les lignes › Conserver les doublons. Ici, les deux lignes de BFO-1008 sont identiques sur toutes les colonnes (même client, même agence, même encours de 1 870 000) : c'est une copie, que l'on peut retirer sans risque.

  1. Revenez sur la requête Septembre et cliquez sur sa dernière étape.
  2. Sélectionnez toutes les colonnes (Ctrl+A dans l'aperçu), puis Accueil › Supprimer les lignes › Supprimer les doublons. Avec toutes les colonnes sélectionnées, seules les lignes identiques en tout point sont retirées.

La requête Septembre complète devient :

// Requête Septembre : le portefeuille de fin septembre, clé nettoyée, copies exactes retirées
let
    Source = Excel.Workbook(File.Contents("C:\Reporting\Comparaison\portefeuille-2026-09.xlsx"), null, true),
    Portefeuille = Source{[Item = "T_Portefeuille", Kind = "Table"]}[Data],
    Types = Table.TransformColumnTypes(Portefeuille, {
        {"Arrêté", type date}, {"Contrat", type text}, {"Client", type text},
        {"Agence", type text}, {"Produit", type text}, {"Encours", type number}}),
    CleNettoyee = Table.TransformColumns(Types, {{"Contrat", each Text.Upper(Text.Trim(_)), type text}}),
    // Supprimer les doublons sur toutes les colonnes : seules les lignes identiques en tout point disparaissent
    SansCopies = Table.Distinct(CleNettoyee)
in
    SansCopies
  • Septembre : 15 lignes, somme de Encours 191 545 000.
  • Doublons_Septembre : aucune ligne. Gardez cette requête : un tableau vide est le résultat attendu.

Une copie exacte se supprime, un doublon de clé s'examine. Si un mois prochain Doublons_Septembre affiche un contrat, c'est que deux lignes portent le même numéro avec des valeurs différentes (deux encours, deux agences). Table.Distinct ne les retire pas, et c'est voulu : il faut comprendre avant de supprimer. Deux tranches d'un même prêt, par exemple, demandent une clé à deux colonnes ou un regroupement par contrat. Retenez aussi que Power Query « ne garantit pas » de conserver la première ligne d'un groupe de doublons, selon Microsoft : ne supprimez jamais sur la seule colonne de clé des lignes qui diffèrent.

Étape 1 — Les prêts sortis : anti gauche

Un prêt sorti est dans le fichier d'août et n'est plus dans celui de septembre. C'est exactement ce que fait l'anti gauche : elle « n'amène que des lignes de la table de gauche qui n'ont pas de lignes correspondantes dans la table de droite » (Microsoft Learn). Le fichier d'août doit donc être à gauche, en haut de la boîte de dialogue.

  1. Rouvrez l'Éditeur Power Query et sélectionnez Aout dans le volet Requêtes.
  2. Accueil › Combiner, flèche à côté de Fusionner les requêtes › Fusionner les requêtes en tant que nouvelles (libellé variable selon la version, par exemple « comme nouvelles »). Cette commande crée une nouvelle requête au lieu d'ajouter une étape à Aout.
  3. Dans la boîte de dialogue Fusionner : en haut, la table Aout ; cliquez sur l'en-tête Contrat. En bas, choisissez Septembre et cliquez sur son en-tête Contrat.
  4. Dans la liste Type de jointure, choisissez Anti gauche.
  5. Lisez le message en bas de la boîte de dialogue avant de cliquer sur OK. Microsoft le juge « essentiel pour comprendre le résultat obtenu ». Pour une anti gauche, il compte les lignes de la première table qui seront gardées : ici 2 sur 15. Dans l'exemple de Microsoft, il se lit « La sélection sélectionne 3 de 4 lignes dans le premier tableau » ; la formulation varie selon la version.
  6. La nouvelle requête contient les colonnes d'Aout et une colonne Septembre, dont chaque cellule est une table vide : l'anti gauche « n'apporte aucune valeur de la table de droite ». Clic droit sur l'en-tête Septembre › Supprimer.
  7. Nommez la requête Prets_sortis.
// Requête Prets_sortis : dans Aout, absents de Septembre
let
    Fusion = Table.NestedJoin(Aout, {"Contrat"}, Septembre, {"Contrat"}, "Septembre", JoinKind.LeftAnti),
    Sortis = Table.RemoveColumns(Fusion, {"Septembre"})
in
    Sortis

Étape 2 — Les nouveaux prêts : anti droite

Un nouveau prêt est dans septembre et n'était pas dans août. Deux façons d'y arriver :

  • Anti droite, avec Aout toujours en haut. Elle « apporte uniquement des lignes de la table de droite qui n'ont pas de lignes correspondantes à partir de la table de gauche ». Mais le résultat est déroutant : les colonnes d'Aout sont vides (null), et les données des nouveaux prêts sont rangées dans la colonne Septembre, qu'il faut développer avant de supprimer les colonnes vides. Le message du bas compte aussi à l'envers : il annonce les lignes de la deuxième table exclues (13 sur 15).
  • Anti gauche en inversant les tables : Septembre en haut, Aout en bas. Le résultat a directement les colonnes de septembre. C'est la méthode conseillée.
  1. Sélectionnez Septembre dans le volet Requêtes, puis Accueil › Combiner › Fusionner les requêtes en tant que nouvelles.
  2. En haut : Septembre, en-tête Contrat. En bas : Aout, en-tête Contrat. Type de jointure : Anti gauche. Le message annonce 2 lignes sur 15 de la première table. OK.
  3. Supprimez la colonne Aout (des tables vides) et nommez la requête Nouveaux_prets.
// Requête Nouveaux_prets : dans Septembre, absents de Aout (anti gauche, tables inversées)
let
    Fusion = Table.NestedJoin(Septembre, {"Contrat"}, Aout, {"Contrat"}, "Aout", JoinKind.LeftAnti),
    Nouveaux = Table.RemoveColumns(Fusion, {"Aout"})
in
    Nouveaux

Étape 3 — Les encours modifiés : jointure interne et colonne Écart

Reste les prêts présents des deux côtés. La jointure interne « apporte uniquement des lignes correspondantes des tables de gauche et de droite ». On met septembre à gauche, on va chercher l'encours d'août, et on calcule l'écart.

  1. Sélectionnez Septembre, puis Accueil › Combiner › Fusionner les requêtes en tant que nouvelles. En haut : Septembre, Contrat ; en bas : Aout, Contrat ; type de jointure Interne. Le message annonce 13 correspondances. OK.
  2. Cliquez sur l'icône à deux flèches de l'en-tête Aout (Développer). Décochez (Sélectionner toutes les colonnes), cochez seulement Encours, et laissez cochée la case Utiliser le nom de la colonne d'origine comme préfixe : le préfixe donne à l'encours d'août un nom distinct, Aout.Encours, car la table a déjà une colonne Encours (celle de septembre) et une table ne peut pas avoir deux colonnes du même nom. OK.
  3. Renommez Aout.Encours en Encours août et Encours en Encours septembre (double-clic sur l'en-tête).
  4. Ajouter une colonne › Colonne personnalisée. Nom : Écart ; formule : Number.Round([Encours septembre] - [Encours août], 2). OK, puis type Nombre décimal. L'arrondi au centime évite d'afficher −0,399999999… au lieu de −0,40, un effet du calcul en virgule flottante.
  5. Nommez la requête Prets_communs.
// Requête Prets_communs : les prêts présents dans les deux fichiers, avec l'écart d'encours
let
    Fusion = Table.NestedJoin(Septembre, {"Contrat"}, Aout, {"Contrat"}, "Aout", JoinKind.Inner),
    EncoursAout = Table.ExpandTableColumn(Fusion, "Aout", {"Encours"}, {"Encours août"}),
    Renomme = Table.RenameColumns(EncoursAout, {{"Encours", "Encours septembre"}}),
    // Écart = septembre − août : négatif = baisse (remboursement), positif = hausse (déblocage)
    AvecEcart = Table.AddColumn(Renomme, "Écart", each Number.Round([Encours septembre] - [Encours août], 2), type number)
in
    AvecEcart
  • 13 lignes. Somme de Écart : −1 310 000,40.
  • Trois lignes à écart nul ou presque : BFO-1002 (0), BFO-1013 (0) et BFO-1006 (−0,40).

Filtrer les écarts, avec une tolérance d'arrondi

BFO-1006 passe de 3 125 000,40 à 3 125 000 : un écart de 40 centimes, venu d'un calcul d'intérêts ou d'un arrondi dans le système, pas d'un vrai mouvement. Filtrer sur « Écart différent de 0 » le ferait passer pour un encours modifié. On fixe donc une tolérance, ici 1 FCFA, et on l'écrit noir sur blanc dans la requête, pour qu'elle reste visible et discutable.

  1. Clic droit sur Prets_communs › Référence ; nommez la requête Encours_modifies.
  2. Flèche de l'en-tête Écart › Filtres numériques › Supérieur à… Dans la boîte Filtrer les lignes : première condition est supérieur à 1, cochez Ou, seconde condition est inférieur à -1. OK.
  3. Triez par Écart croissant : les plus fortes baisses en tête.
// Requête Encours_modifies : écarts au-delà de la tolérance
let
    Tolerance = 1,    // en FCFA : à documenter et à faire valider
    Source = Prets_communs,
    Modifies = Table.SelectRows(Source, each Number.Abs([Écart]) > Tolerance),
    Tri = Table.Sort(Modifies, {{"Écart", Order.Ascending}, {"Contrat", Order.Ascending}})
in
    Tri

Étape 4 — Le pont d'encours et le contrôle à zéro

Trois listes, c'est bien. Mais expliquent-elles toute la variation de l'encours ? Le pont (on dit aussi « tableau de passage ») le vérifie :

Encours d'août − prêts sortis + nouveaux prêts + hausses − baisses ± écarts sous la tolérance = encours de septembre

La dernière ligne du pont compare l'encours ainsi calculé à celui du fichier de septembre. Elle doit valoir 0, en montant et en nombre de contrats. Les écarts sous la tolérance n'y sont pas oubliés : ils ont leur propre ligne. La tolérance sert à ne pas lister les centimes, pas à les faire disparaître.

  1. Données › Obtenir des données › À partir d'autres sources › Requête vide (ou, dans l'éditeur, Accueil › Nouvelle source › Autres sources › Requête vide).
  2. Accueil › Éditeur avancé : remplacez tout le contenu par le code ci-dessous, puis Terminé. Nommez la requête Pont_Encours.
// Requête Pont_Encours : de l'encours d'août à celui de septembre, avec un contrôle qui doit valoir 0
let
    Tolerance = 1,
    // Somme qui renvoie 0 (et non null) pour une liste vide
    Somme = (valeurs as list) as number => List.Sum({0} & valeurs),
    Ecarts = Prets_communs[Écart],
    Hausses = List.Select(Ecarts, each _ > Tolerance),
    Baisses = List.Select(Ecarts, each _ < -Tolerance),
    Arrondis = List.Select(Ecarts, each Number.Abs(_) <= Tolerance),
    EncoursAout = Somme(Aout[Encours]),
    EncoursSept = Somme(Septembre[Encours]),
    Sortis = Somme(Prets_sortis[Encours]),
    Nouveaux = Somme(Nouveaux_prets[Encours]),
    Calcule = EncoursAout - Sortis + Nouveaux + Somme(Hausses) + Somme(Baisses) + Somme(Arrondis),
    NbCalcule = Table.RowCount(Aout) - Table.RowCount(Prets_sortis) + Table.RowCount(Nouveaux_prets),
    Pont = #table(
        type table [Ligne = text, Contrats = Int64.Type, Montant = number],
        {
            {"Encours au 31/08/2026", Table.RowCount(Aout), EncoursAout},
            {"− Prêts sortis", Table.RowCount(Prets_sortis), -Sortis},
            {"+ Nouveaux prêts", Table.RowCount(Nouveaux_prets), Nouveaux},
            {"+ Hausses d'encours", List.Count(Hausses), Somme(Hausses)},
            {"− Baisses d'encours", List.Count(Baisses), Somme(Baisses)},
            {"± Écarts sous la tolérance", List.Count(Arrondis), Somme(Arrondis)},
            {"= Encours calculé au 30/09/2026", NbCalcule, Calcule},
            {"Encours du fichier au 30/09/2026", Table.RowCount(Septembre), EncoursSept},
            {"Contrôle (doit valoir 0)", NbCalcule - Table.RowCount(Septembre), Number.Round(Calcule - EncoursSept, 2)}
        })
in
    Pont

Dans la colonne Contrats, seules les entrées et les sorties changent le nombre de prêts : 15 − 2 + 2 = 15. Les lignes de hausses, de baisses et d'écarts sous la tolérance comptent des prêts déjà présents (1 + 9 + 3 = les 13 prêts communs). Chargez le pont dans une feuille : Accueil › Fermer et charger. Faites de même pour Prets_sortis, Nouveaux_prets et Encours_modifies ; laissez Prets_communs et les requêtes de doublons en connexion uniquement (au besoin, Données › Requêtes et connexions, clic droit › Charger dans…).

Le contrôle attrape les erreurs de rapprochement. Sans la suppression de la ligne en double, par exemple, la jointure interne renvoie 14 lignes au lieu de 13 et le contrôle affiche −1 contrat et −1 980 000 : le fichier de septembre compte la copie en trop (1 870 000), et le calcul compte deux fois la baisse de BFO-1008 (110 000 de trop).

Ce que le contrôle ne voit pas. Sans le nettoyage de la clé, le pont tombe quand même à 0 : BFO-1005 compte une fois en sortie (−12 300 000) et une fois en entrée (+11 900 000), et le total est juste. Seules les listes sont fausses (3 sortis, 3 nouveaux). Un contrôle à zéro prouve que tout est expliqué, pas que tout est bien expliqué. Relisez donc les sortis et les nouveaux : un prêt sorti et un nouveau prêt du même client, de la même agence et du même produit trahissent presque toujours une clé mal nettoyée.

Le même raisonnement, pour le rapprochement comptable. Ces jointures et ce contrôle à zéro sont au cœur du module 7 de la formation « Power Query pour le reporting bancaire » : rapprocher la balance et l'encours par mois et par compte, avec une tolérance documentée, comprendre pourquoi un rapprochement en total ne suffit pas, produire la liste des écarts à justifier et remonter d'un écart aux contrats. Le module 3, lui, traite le nettoyage en amont : normaliser les codes, isoler les erreurs, dédoublonner au bon moment. Voir le programme et le tarif de la formation

Variante : tout en une seule requête (externe complète et colonne Statut)

Les trois listes séparées sont pratiques pour faire justifier chaque catégorie. Pour un état de synthèse, une seule table, avec une ligne par contrat et un statut, est souvent plus lisible. La jointure externe complète « intègre toutes les lignes des tables de gauche et de droite », et Microsoft précise, pour JoinKind.FullOuter, que « les lignes qui n'ont pas de correspondance dans l'autre table sont jointes avec une ligne par défaut contenant des valeurs Null pour toutes ses colonnes ». Il suffit donc de regarder quel côté est vide :

  • rien en septembre : Supprimé ;
  • rien en août : Ajouté ;
  • des deux côtés, écart au-delà de la tolérance : Modifié ; sinon Identique.

Créez une requête vide (comme à l'étape 4), collez le code ci-dessous dans l'Éditeur avancé, nommez la requête Comparaison, puis Fermer et charger. Elle s'appuie sur les requêtes Aout et Septembre de l'étape 0, déjà nettoyées.

// Requête Comparaison : une ligne par contrat, avec un statut Ajouté / Supprimé / Modifié / Identique
let
    Tolerance = 1,
    Colonnes = {"Contrat", "Client", "Agence", "Produit", "Encours"},
    Fusion = Table.NestedJoin(
        Table.SelectColumns(Aout, Colonnes), {"Contrat"},
        Table.SelectColumns(Septembre, Colonnes), {"Contrat"},
        "Sept", JoinKind.FullOuter),
    // Les colonnes de septembre arrivent préfixées « S. » ; elles valent null pour un prêt sorti
    Developpe = Table.ExpandTableColumn(Fusion, "Sept", Colonnes,
        {"S.Contrat", "S.Client", "S.Agence", "S.Produit", "S.Encours"}),
    Lignes = Table.TransformRows(Developpe, (r) =>
        let
            EnAout = r[Contrat] <> null,
            EnSept = r[S.Contrat] <> null,
            Ecart = Number.Round((if EnSept then r[S.Encours] else 0) - (if EnAout then r[Encours] else 0), 2)
        in
            [
                Contrat = if EnAout then r[Contrat] else r[S.Contrat],
                Client = if EnAout then r[Client] else r[S.Client],
                Agence = if EnAout then r[Agence] else r[S.Agence],
                Produit = if EnAout then r[Produit] else r[S.Produit],
                #"Encours août" = r[Encours],
                #"Encours septembre" = r[S.Encours],
                Écart = Ecart,
                Statut =
                    if not EnSept then "Supprimé"
                    else if not EnAout then "Ajouté"
                    else if Number.Abs(Ecart) > Tolerance then "Modifié"
                    else "Identique"
            ]),
    Comparaison = Table.FromRecords(Lignes, type table [
        Contrat = text, Client = text, Agence = text, Produit = text,
        #"Encours août" = nullable number, #"Encours septembre" = nullable number,
        Écart = number, Statut = text]),
    Tri = Table.Sort(Comparaison, {{"Statut", Order.Ascending}, {"Contrat", Order.Ascending}})
in
    Tri

Pour un prêt ajouté, les colonnes d'août sont vides : le code reprend donc le contrat, le client, l'agence et le produit du côté où ils existent. L'écart d'un prêt sorti vaut moins son encours d'août, celui d'un nouveau prêt son encours de septembre : la somme de la colonne Écart est ainsi égale à la variation totale de l'encours.

Afficher les différences en couleur

Power Query calcule, Excel met en forme. Une fois la requête Comparaison chargée dans une feuille, la mise en forme conditionnelle fait ressortir les différences, et elle suit les données à chaque actualisation. Dans le tableau chargé, les colonnes vont de A (Contrat) à H (Statut) ; Écart est en G.

  1. Le statut : sélectionnez les cellules de la colonne Statut (H2:H18), puis Accueil › Mise en forme conditionnelle › Règles de mise en surbrillance des cellules › Texte qui contient… Saisissez Supprimé et choisissez Remplissage rouge clair avec texte rouge foncé. Recommencez avec Ajouté (Remplissage vert avec texte vert foncé) et Modifié (Remplissage jaune avec texte jaune foncé).
  2. La ligne entière, si vous préférez : sélectionnez A2:H18, puis Mise en forme conditionnelle › Nouvelle règle › Utiliser une formule pour déterminer pour quelles cellules le format sera appliqué, formule =$H2="Modifié", bouton Format… pour la couleur. Le $ devant H fixe la colonne : chaque cellule de la ligne regarde le statut de sa ligne.
  3. Le sens de l'écart : sélectionnez G2:G18, Règles de mise en surbrillance des cellules › Inférieur à… -1 en rouge, puis Supérieur à… 1 en vert. Avec ces seuils, les écarts sous la tolérance restent sans couleur.

Pour revoir ou corriger les règles : Mise en forme conditionnelle › Gérer les règles, qui ouvre le Gestionnaire des règles de mise en forme conditionnelle. Après une actualisation qui ajoute des lignes, vérifiez-y la zone S'applique à : elle doit couvrir toute la colonne du tableau.

Comparer sans Power Query

Avec RECHERCHEV ou EQUIV, dans la feuille

Copiez les deux tableaux dans un même classeur, nommez-les T_Aout et T_Sept, puis ajoutez une colonne de formule à chacun :

  • dans T_Aout, l'encours de septembre, ou « Sorti » : =SIERREUR(RECHERCHEV([@Contrat];T_Sept[[Contrat]:[Encours]];5;FAUX);"Sorti") ;
  • dans T_Sept, les nouveaux prêts : =SI(ESTNA(EQUIV([@Contrat];T_Aout[Contrat];0));"Nouveau";"").

Cela dépanne pour un contrôle ponctuel, avec trois limites. Il faut deux formules, une par sens. La clé n'est pas nettoyée : « BFO-1005␣ » ne trouve pas « BFO-1005 », et le prêt passe pour sorti. Et RECHERCHEV s'arrête à la première ligne trouvée : un doublon de clé passe inaperçu, là où une jointure le fait apparaître. Le guide RECHERCHEV avec Power Query détaille le passage de la formule à la fusion de requêtes.

Avec l'outil Comparer les feuilles de calcul de Microsoft

Microsoft propose un outil de comparaison de classeurs, Spreadsheet Compare (« Comparer les feuilles de calcul »), accessible par l'onglet Inquire › Compare Files. L'aide française reprend ces libellés anglais sur une page et les traduit sur une autre (« Demande de renseignements ») : fiez-vous à votre ruban. Deux réserves avant de compter dessus :

  • Sa disponibilité. D'après les pages du support Microsoft consultées le 22/10/2026, il est « disponible uniquement dans Excel pour Windows », dans les applications Microsoft 365 pour les grandes entreprises et les éditions équivalentes, et la page de l'outil vise ses versions 2013, 2016, 2019 et 2021. L'onglet Inquire doit en outre être activé (Fichier › Options › Compléments, liste Compléments COM), et Microsoft prévient que l'administrateur de votre organisation peut l'avoir rendu indisponible. Sur d'autres éditions de Microsoft 365, il peut donc être absent.
  • Ce qu'il compare. Selon Microsoft, il montre « les différences, cellule par cellule, entre deux classeurs », chaque feuille étant comparée à la feuille correspondante de l'autre fichier, et les modifications sont mises en couleur selon leur type. C'est précieux pour savoir ce qui a changé dans un modèle ou dans ses formules. Mais il compare des cellules, pas des lignes rapprochées par une clé : il ne vous donne pas directement la liste des prêts sortis, nouveaux ou modifiés avec leurs montants, ni un total qui se contrôle, et il se relance à la main chaque mois.

Pour deux extractions mensuelles, Power Query reste la méthode la plus sûre : elle rapproche par la clé, quel que soit l'ordre des lignes, et se refait d'un clic le mois suivant.

Questions fréquentes

Comment trouver les doublons entre deux fichiers Excel ?

Si « doublons » veut dire les lignes présentes dans les deux fichiers, c'est une jointure interne : fusionnez les deux requêtes sur la clé avec le type Interne. Sur l'exemple, 13 contrats sont présents en août et en septembre. Si vous cherchez une clé répétée à l'intérieur d'un même fichier, c'est un regroupement : Accueil › Regrouper par sur la clé, opération Compter les lignes, puis un filtre « supérieur à 1 ».

Et si la clé tient sur plusieurs colonnes ?

Dans la boîte de dialogue Fusionner, maintenez Ctrl et cliquez sur les colonnes de la clé, par exemple Agence puis Contrat, dans la table du haut, puis dans le même ordre dans la table du bas. Microsoft le précise : la première colonne sélectionnée à gauche est mise en correspondance avec la première sélectionnée à droite, et ainsi de suite ; sinon, les résultats de la jointure peuvent être incorrects. Des petits numéros 1, 2… s'affichent à côté des en-têtes pour rappeler l'ordre.

Comment refaire la comparaison le mois suivant ?

Le plus simple est de donner aux fichiers des noms fixes, par exemple portefeuille-precedent.xlsx et portefeuille-courant.xlsx : chaque mois, on remplace les deux fichiers, puis Données › Actualiser tout. Si les noms changent, modifiez le chemin dans Données › Obtenir des données › Paramètres de la source de données, ou dans la ligne Source de chaque requête, puis actualisez. Les requêtes de fusion, le pont et la mise en forme conditionnelle n'ont pas à être refaits.

Peut-on comparer deux listes ou deux colonnes simples de la même façon ?

Oui. Une liste d'une seule colonne est une table d'une seule colonne : l'anti gauche donne les valeurs de la première liste absentes de la seconde, l'anti gauche dans l'autre sens donne l'inverse, et la jointure interne les valeurs communes. Si les deux listes sont dans le même classeur, mettez-les sous forme de tableau et chargez-les avec Données › À partir de Tableau/Plage. Le nettoyage de l'étape 0 reste indispensable.

Et sur Mac ?

La page du support Microsoft sur la fusion de requêtes indique qu'elle s'applique aussi à Excel pour Microsoft 365 pour Mac. Ce guide décrit Excel pour Windows : sur Mac, les menus peuvent différer. L'outil Comparer les feuilles de calcul, lui, n'est proposé que dans Excel pour Windows, selon Microsoft.
