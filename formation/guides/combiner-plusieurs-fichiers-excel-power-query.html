Combiner plusieurs fichiers Excel en un seul avec Power Query

Quatre agences, quatre classeurs, un seul tableau : la méthode pas à pas depuis un dossier, le code M complet, un contrôle des lignes et des totaux de chaque fichier, puis la mise à jour du mois suivant en un clic.

Mis à jour le 22/10/2026 · Données d'exemple 100 % fictives · Excel 2016 ou plus récent, ou Microsoft 365, sous Windows

La réponse en 4 étapes :

  1. Mettez les classeurs à combiner, de même structure, dans un dossier qui ne contient qu'eux.
  2. Données › Obtenir des données › À partir d'un fichier › À partir d'un dossier, choisissez le dossier, puis Transformer les données.
  3. Gardez les seuls fichiers .xlsx (sans les fichiers temporaires « ~$ »), puis Accueil › Combiner › Combiner les fichiers et choisissez le tableau à empiler.
  4. Tirez le nom de l'agence de la colonne Source.Name, typez les colonnes, Fermer et charger. Le mois suivant : remplacez les fichiers, puis Données › Actualiser tout.

Sur l'exemple fictif de ce guide : 4 fichiers, 20 lignes, 374 950 000 FCFA d'encours.

Le besoin : un tableau unique, qui se met à jour d'un clic

Chaque fin de mois, le service reporting de la Banque Fictive de l'Ouest (BFO), une banque imaginaire, reçoit un classeur d'encours de chacune de ses quatre agences : Flamboyant, Ronier, Filao et Acajou. Les ouvrir un par un et copier-coller les lignes dans un classeur de synthèse prend du temps et laisse passer des erreurs : une agence oubliée, une colonne décalée, des lignes collées deux fois.

Power Query fait ce travail à votre place. Microsoft le décrit ainsi : « Utilisez Power Query pour combiner plusieurs fichiers avec le même schéma stocké dans un seul dossier dans une seule table. » Le résultat visé ici :

  • un seul tableau, avec toutes les lignes des quatre agences ;
  • une colonne Agence, tirée du nom de chaque fichier, pour savoir d'où vient chaque ligne ;
  • un contrôle par fichier : nombre de lignes et total de l'encours, à comparer à ce que chaque agence annonce ;
  • une mise à jour d'un clic : le mois suivant, on remplace les fichiers du dossier, puis Données › Actualiser tout.

Pourquoi un tableau Excel plutôt qu'une simple plage ? Parce qu'il a un nom stable (Encours), qu'il s'agrandit quand l'agence ajoute des lignes, et que Power Query le lit sans le bloc de contrôle placé à côté. Si vos agences envoient des plages sans tableau, la variante par feuille plus bas montre comment lire une feuille entière.

Préparer le dossier : rien que les fichiers à combiner

C'est la règle n° 1. Microsoft écrit : « Assurez-vous que tous les fichiers que vous souhaitez combiner sont contenus dans un dossier dédié, sans fichiers superflus. Sinon, tous les fichiers du dossier et les sous-dossiers que vous sélectionnez sont inclus dans les données à combiner. » La fonction M qui lit le dossier, Folder.Files, renvoie de même « une ligne pour chaque fichier trouvé dans le dossier spécifié et tous ses sous-dossiers ».

Quelques conventions qui évitent la plupart des pannes :

  • Un dossier par flux : ici Encours_Agences, qui ne reçoit que les encours des agences. Votre classeur de reporting est enregistré ailleurs, sinon il serait combiné avec les autres.
  • Un nom de fichier fixe par agence, en minuscules et sans espace : agence-<nom>.xlsx. Pas de date dans le nom : elle est dans la colonne Arrêté. Le nom ne change donc pas d'un mois à l'autre, et l'on en tire le nom de l'agence.
  • Les mois précédents archivés hors du dossier, et surtout pas dans un sous-dossier : ils seraient relus.
  • Un modèle commun envoyé aux agences : même nom de tableau, mêmes en-têtes, au caractère près.

Choisissez le dossier Encours_Agences, pas le dossier parent. Avec combiner-fichiers-excel-exemple, Power Query lirait aussi les sous-dossiers : le classeur des onglets, qui n'a pas de tableau Encours, provoquerait une erreur ; et même sans lui, les quatre classeurs d'octobre, aux mêmes noms de fichier, s'ajouteraient à ceux de septembre (41 lignes au lieu de 20, sur deux arrêtés).

Étape 1 — Se connecter au dossier

  1. Ouvrez un classeur vierge : ce sera votre classeur de reporting. Enregistrez-le en dehors du dossier Encours_Agences.
  2. Données › Obtenir des données › À partir d'un fichier › À partir d'un dossier (Excel 2016 : Données › Nouvelle requête › À partir d'un fichier › À partir d'un dossier).
  3. Cliquez sur Parcourir, sélectionnez le dossier Encours_Agences, puis validez.
  4. Une fenêtre liste les fichiers du dossier, avec les colonnes Content (le contenu du fichier), Name, Extension, Date accessed, Date modified, Date created, Attributes et Folder Path. Vérifiez que les quatre classeurs y sont, et rien d'autre.
  5. Cliquez sur Transformer les données, et non sur Combiner : on filtre d'abord, on combine ensuite.

Le bouton Combiner propose trois commandes : Combiner et transformer les données, Combiner et charger, Combiner et charger dans… Elles vont plus vite, mais elles combinent tout ce que contient le dossier. La page Microsoft Learn du connecteur Dossier le confirme : pour exclure des fichiers, sélectionnez d'abord Transformer les données et filtrez la table des fichiers avant de combiner.

Étape 2 — Ne garder que les bons fichiers

Dans l'Éditeur Power Query, la requête affiche une ligne par fichier. Deux filtres suffisent :

  1. Colonne Extension : cliquez sur la flèche de l'en-tête, ne laissez cochée que la valeur .xlsx, puis OK.
  2. Colonne Name : flèche de l'en-tête › Filtres textuels › Ne commence pas par…, saisissez ~$, puis OK.

Le second filtre vise un piège classique. Quand un classeur est ouvert dans Excel, Excel crée à côté de lui un petit fichier temporaire au nom commençant par « ~$ », par exemple ~$agence-ronier.xlsx. Ce n'est pas un vrai classeur : Power Query ne sait pas le lire comme tel, et l'actualisation échoue. Ces fichiers sont d'ordinaire masqués, et la combinaison automatique ajoute en général une étape qui écarte les fichiers masqués ; le filtre sur le nom, lui, ne dépend pas de cet attribut. Dans l'Éditeur avancé (Accueil › Éditeur avancé), la requête ressemble alors à ceci :

let
    Source = Folder.Files("C:\Reporting\Encours_Agences"),
    #"Lignes filtrées" = Table.SelectRows(Source, each [Extension] = ".xlsx"),
    #"Lignes filtrées1" = Table.SelectRows(#"Lignes filtrées", each not Text.StartsWith([Name], "~$"))
in
    #"Lignes filtrées1"

Le chemin C:\Reporting\Encours_Agences est un exemple : Power Query écrit celui du dossier que vous avez choisi.

Étape 3 — Combiner les fichiers

  1. Cliquez sur l'icône à deux flèches dans l'en-tête de la colonne Content (Combiner les fichiers), ou sur Accueil › Combiner › Combiner les fichiers.
  2. La boîte de dialogue Combiner les fichiers s'ouvre. Dans la liste Exemple de fichier, laissez Premier fichier : ici agence-acajou.xlsx.
  3. À gauche, Power Query affiche le contenu de ce fichier : le tableau Encours (icône de tableau) et la feuille Portefeuille (icône de feuille). Sélectionnez le tableau Encours : la feuille contient aussi le bloc de contrôle.
  4. Laissez décochée la case Ignorer les fichiers avec des erreurs : mieux vaut voir une erreur que perdre une agence sans le savoir. Cliquez sur OK.

Power Query crée alors plusieurs requêtes, visibles dans le volet Requêtes, à gauche. D'après Microsoft Learn et le support Microsoft :

Les quatre premières sont rangées à part, dans un groupe nommé d'après le dossier (« Transformer le fichier à partir de Encours_Agences »), avec un sous-groupe « Requêtes d'assistance ». Ne supprimez rien : la requête finale en dépend. Les libellés exacts peuvent varier un peu selon la version d'Excel.

Dans la requête finale, Power Query appelle la fonction sur chaque fichier, renomme la colonne Name en Source.Name, puis développe les tables obtenues en colonnes. Un détail de cette dernière étape compte beaucoup : dans l'Éditeur avancé, elle contient Table.ColumnNames(#"Transformer le fichier"(#"Exemple de fichier")). Autrement dit, la liste des colonnes est celle du fichier d'exemple. Deux conséquences sur nos données :

  • Filao, aux colonnes dans un autre ordre, ne pose aucun problème. Microsoft le précise : « Les colonnes n'ont pas besoin d'être dans le même ordre, car la correspondance est effectuée par les noms de colonne. »
  • La colonne Commentaire de Ronier disparaît sans message. Elle n'existe pas dans le fichier d'exemple (Acajou), donc elle n'est pas développée. Si vous aviez choisi agence-ronier.xlsx comme exemple, elle serait présente, et vide pour les trois autres agences. La variante en code M règle la question.

Étape 4 — Le nom de l'agence et les types

La colonne Source.Name contient le nom du fichier d'origine de chaque ligne : gardez-la. On en tire une colonne Agence plus lisible.

  1. Sélectionnez la colonne Source.Name, puis Ajouter une colonne › Extraire › Texte entre les délimiteurs. Délimiteur de début : agence- ; délimiteur de fin : .xlsx. OK.
  2. Double-cliquez sur l'en-tête de la nouvelle colonne et renommez-la Agence. Puis Transformer › Format › Mettre en majuscule chaque mot : « flamboyant » devient « Flamboyant ».
  3. Autre méthode, si vos noms de fichiers sont moins réguliers : Ajouter une colonne › Dupliquer la colonne sur Source.Name, puis Transformer › Remplacer les valeurs deux fois (agence- par rien, puis .xlsx par rien).
  4. Vérifiez les types, avec l'icône à gauche de chaque en-tête : Arrêté en Date ; Code agence, Contrat, Client, Produit et Agence en Texte ; Encours en Nombre décimal ; Jours de retard en Nombre entier. L'étape Type modifié ajoutée automatiquement a pu typer Code agence en nombre : si Excel demande s'il faut remplacer l'étape existante, choisissez Remplacer l'actuelle. Une nouvelle étape partirait des nombres déjà convertis et donnerait « 4 » au lieu de « 004 ».
  5. Accueil › Fermer et charger. Le tableau combiné s'affiche dans une nouvelle feuille.

Le Code agence mérite une attention particulière : « 001 » est un code, pas une quantité. En Nombre entier, il deviendrait 1 et ne correspondrait plus à aucune table de référence. Un code se garde toujours en texte. Le calcul de la colonne Agence, en code M, tient en une ligne : Text.Proper(Text.BetweenDelimiters([Source.Name], "agence-", ".xlsx")).

  • 20 lignes et 9 colonnes : Source.Name, Arrêté, Code agence, Contrat, Client, Produit, Encours, Jours de retard, Agence.
  • Pas de colonne Commentaire (le fichier d'exemple, Acajou, n'en a pas).
  • Somme de la colonne Encours : 374 950 000. Codes agence « 001 » à « 004 », en texte.
  • Lignes de Filao complètes, malgré l'ordre différent de ses colonnes.

La variante en code M, sans requêtes d'aide

La méthode des boutons crée cinq requêtes et ignore les colonnes absentes du fichier d'exemple. Pour un reporting mensuel, une seule requête, lisible de haut en bas, est souvent plus simple à maintenir. Elle repose sur trois fonctions documentées : Folder.Files (la liste des fichiers), Excel.Workbook (le contenu d'un classeur) et Table.Combine (l'empilement).

  1. Données › Obtenir des données › À partir d'autres sources › Requête vide (Excel 2016 : Données › Nouvelle requête › À partir d'autres sources › Requête vide).
  2. Accueil › Éditeur avancé : remplacez tout le contenu par le code ci-dessous, puis corrigez la ligne Dossier avec le chemin de votre dossier. Terminé.
  3. Dans Paramètres de requête › Propriétés › Nom, à droite, nommez la requête Encours_Agences (ou Encours_Agences_M si la version des boutons existe déjà dans le classeur).
  4. Accueil › Fermer et charger.
// Requête Encours_Agences (variante M) : tous les classeurs du dossier en un seul tableau
let
    // Le seul chemin à adapter : le dossier qui ne contient que les fichiers à combiner
    Dossier = "C:\Reporting\Encours_Agences",
    Fichiers = Folder.Files(Dossier),

    // Les classeurs .xlsx seulement : ni fichiers masqués, ni fichiers temporaires « ~$ » d'un classeur ouvert
    Classeurs = Table.SelectRows(Fichiers, each Text.Lower([Extension]) = ".xlsx"
        and not Text.StartsWith([Name], "~$")
        and [Attributes]?[Hidden]? <> true),

    // Pour chaque fichier : le tableau « Encours », en-têtes sans espace superflu, plus le nom du fichier
    AvecTables = Table.AddColumn(Classeurs, "Données", each
        let
            NomFichier = [Name],
            Encours = Excel.Workbook([Content], null, true){[Item = "Encours", Kind = "Table"]}[Data],
            EnTetes = Table.TransformColumnNames(Encours, Text.Trim)
        in
            Table.AddColumn(EnTetes, "Source.Name", each NomFichier, type text)),

    // Empiler : la table finale réunit les colonnes de tous les fichiers (null là où un fichier n'en a pas)
    Combine = Table.Combine(AvecTables[Données]),

    // L'agence, tirée du nom de fichier : « agence-ronier.xlsx » donne « Ronier »
    AvecAgence = Table.AddColumn(Combine, "Agence",
        each Text.Proper(Text.BetweenDelimiters([Source.Name], "agence-", ".xlsx")), type text),

    // Types explicites ; Code agence reste du texte pour garder « 001 »
    Types = Table.TransformColumnTypes(AvecAgence, {
        {"Arrêté", type date}, {"Code agence", type text}, {"Contrat", type text}, {"Client", type text},
        {"Produit", type text}, {"Encours", type number}, {"Jours de retard", Int64.Type}}),

    // Source.Name et Agence en tête ; les autres colonnes, y compris celles en plus, à la suite
    Ordre = Table.ReorderColumns(Types,
        {"Source.Name", "Agence"} & List.RemoveItems(Table.ColumnNames(Types), {"Source.Name", "Agence"}))
in
    Ordre

Ce qu'il faut retenir du code :

  • {[Item = "Encours", Kind = "Table"]} choisit le tableau nommé Encours. Excel.Workbook renvoie une ligne par feuille, par tableau et par nom défini ; préciser Kind = "Table" évite de tomber sur une feuille qui porterait le même nom.
  • null, true : les deux paramètres de Excel.Workbook. Le premier (useHeaders) est inutile pour un tableau, qui a déjà ses en-têtes. Le second laisse les colonnes non typées : on type une seule fois, à la fin. Microsoft déconseille d'ailleurs useHeaders, qui « convertit les nombres et les dates en texte à l'aide de la culture actuelle », au profit de Table.PromoteHeaders (utilisé plus bas, pour les feuilles).
  • Table.TransformColumnNames(…, Text.Trim) retire les espaces au début et à la fin des en-têtes : « Encours » suivi d'un espace redevient « Encours ».
  • Table.Combine : selon sa documentation, la table obtenue a « une union des types d'entrée », c'est-à-dire toutes les colonnes de tous les fichiers. L'exemple de Microsoft montre qu'une colonne absente d'une table y vaut null. La colonne Commentaire de Ronier est donc conservée.
  • 20 lignes et 10 colonnes : Source.Name, Agence, Arrêté, Code agence, Contrat, Client, Produit, Encours, Jours de retard, Commentaire.
  • Commentaire rempli sur deux lignes seulement : RO-0202 (« Relance écrite le 22/09/2026 ») et RO-0204 (« Remboursement anticipé partiel en août »). Il vaut null sur les 18 autres lignes.
  • Somme de la colonne Encours : 374 950 000.

L'ordre des lignes suit celui des fichiers renvoyé par le dossier ; ne comptez pas dessus et triez si besoin (en-tête de colonne › Tri croissant).

Contrôler chaque fichier : nombre de lignes et total

Un fichier manquant, un fichier en double ou une colonne renommée ne déclenchent pas toujours d'erreur : ils changent les chiffres. D'où une requête de contrôle, une ligne par fichier, à comparer au bloc « Contrôle de l'agence » de chaque classeur (ou aux chiffres que les agences vous envoient).

  1. Dans le volet Requêtes, clic droit sur Encours_Agences › Référence. Renommez la nouvelle requête Controle_Encours.
  2. Accueil › Regrouper par, option Avancé. Regroupez par Source.Name, puis Ajouter un regroupement sur Agence.
  3. Agrégations, une par ligne (bouton Ajouter une agrégation pour les suivantes) : Lignes avec l'opération Compter les lignes ; Total encours, Somme de Encours ; Arrêté, Max de Arrêté. OK, puis Fermer et charger.

La même requête en code M, avec une colonne de plus qui compte les encours vides :

// Requête Controle_Encours : une ligne par fichier, à comparer au bloc « Contrôle de l'agence » de chaque classeur
let
    Source = Encours_Agences,
    ParFichier = Table.Group(Source, {"Source.Name", "Agence"}, {
        {"Lignes", each Table.RowCount(_), Int64.Type},
        {"Total encours", each List.Sum([Encours]), type nullable number},
        {"Encours vides", each List.Count(List.Select([Encours], each _ = null)), Int64.Type},
        {"Arrêté", each List.Max([Arrêté]), type nullable date}}),
    Tri = Table.Sort(ParFichier, {{"Source.Name", Order.Ascending}})
in
    Tri

La ligne de total n'est pas produite par la requête : dans Excel, cliquez dans le tableau chargé, puis Création de tableau › Ligne Total. Dans la ligne ajoutée, choisissez Somme sous Lignes, Total encours et Encours vides, et Aucun sous Arrêté : une somme de dates n'a pas de sens. Comment lire le contrôle :

  • Lignes ou total différents du chiffre de l'agence : fichier incomplet, ou lignes en double.
  • Une ligne de trop dans le contrôle : un fichier en trop dans le dossier (une copie, un ancien mois).
  • Encours vides supérieur à 0 : l'en-tête Encours a changé dans ce fichier, ou des montants n'y sont pas saisis.
  • Arrêté différent de la date attendue : le fichier n'a pas été remplacé.

Le mois suivant : remplacer les fichiers, puis actualiser

C'est là que la méthode rapporte. Testez-la avec les fichiers d'octobre fournis :

  1. Fermez les classeurs des agences s'ils sont ouverts.
  2. Copiez les quatre fichiers du dossier Mois_suivant_2026-10 dans Encours_Agences. Quand Windows signale que les fichiers existent déjà, choisissez Remplacer les fichiers dans la destination.
  3. Dans votre classeur de reporting : Données › Actualiser tout.

Variante : combiner plusieurs onglets d'un même classeur

Autre cas fréquent : un seul classeur, avec un onglet par agence. Le fichier Onglets\encours-par-onglet.xlsx de l'exemple contient un onglet Synthèse puis quatre onglets d'agence (Flamboyant, Ronier, Filao, Acajou), des plages simples sans tableau. Excel.Workbook liste les onglets avec Kind = "Sheet" : il suffit de les filtrer, de promouvoir la première ligne en en-têtes et d'empiler. Le nom de l'onglet devient l'agence.

  1. Données › Obtenir des données › À partir d'autres sources › Requête vide, puis Accueil › Éditeur avancé.
  2. Collez le code ci-dessous et remplacez le chemin du fichier par le vôtre. Terminé, nommez la requête Encours_Onglets, puis Fermer et charger.
// Requête Encours_Onglets : les onglets d'agence d'un même classeur, empilés
let
    Classeur = Excel.Workbook(File.Contents("C:\Reporting\Onglets\encours-par-onglet.xlsx"), null, true),

    // Les feuilles seulement (ni tableaux ni noms définis), sans l'onglet de synthèse ni les onglets masqués
    Feuilles = Table.SelectRows(Classeur, each [Kind] = "Sheet" and [Item] <> "Synthèse" and not [Hidden]),

    // Chaque feuille : la 1re ligne devient l'en-tête, puis le nom de l'onglet devient l'agence
    AvecTables = Table.AddColumn(Feuilles, "Données", each
        let
            Onglet = [Item],
            Donnees = Table.PromoteHeaders([Data], [PromoteAllScalars = true])
        in
            Table.AddColumn(Donnees, "Agence", each Onglet, type text)),

    Combine = Table.Combine(AvecTables[Données]),
    Types = Table.TransformColumnTypes(Combine, {
        {"Arrêté", type date}, {"Code agence", type text}, {"Contrat", type text}, {"Client", type text},
        {"Produit", type text}, {"Encours", type number}, {"Jours de retard", Int64.Type}})
in
    Types
  • 20 lignes, 374 950 000 d'encours au total : les mêmes chiffres que le dossier de septembre.
  • Colonne Agence = nom de l'onglet : 5 lignes Flamboyant, 4 Ronier, 6 Filao, 5 Acajou.
  • Aucune ligne venue de l'onglet Synthèse.

Sans le filtre sur Synthèse, les lignes de cet onglet (le détail par agence, la ligne Total et la mention sur les données fictives) s'empileraient avec celles des agences : plus de 20 lignes, une « agence » Synthèse et trois colonnes en plus (Onglet, Nombre de contrats, Total encours), vides sur les lignes des agences. La somme de la colonne Encours ne bougerait pas, car la synthèse n'a pas de colonne de ce nom : c'est le nombre de lignes qui alerte. Le code lit le fichier enregistré sur le disque : enregistrez le classeur des onglets avant d'actualiser.

Questions fréquentes

Les colonnes doivent-elles être dans le même ordre dans tous les fichiers ?

Non. Selon Microsoft, « les colonnes n'ont pas besoin d'être dans le même ordre, car la correspondance est effectuée par les noms de colonne ». Les noms, en revanche, doivent être identiques, casse et espaces compris : « Encours » et « encours » sont deux colonnes différentes pour Power Query.

Et sur Mac ?

Prudence. Sur Mac, Power Query demande Excel pour Microsoft 365 à jour. La page du support Microsoft sur Power Query dans Excel pour Mac, consultée le 22/10/2026, liste comme sources d'import le classeur Excel, le texte/CSV, XML, JSON, une base SQL Server, une liste SharePoint Online, OData, une table vide et une requête vide : le dossier local n'y figure pas, même si les dossiers sont cités parmi les sources que l'on peut actualiser. Ce guide décrit Excel pour Windows : sur Mac, l'import d'un dossier peut différer ou ne pas être proposé.

Et pour des fichiers CSV au point-virgule ?

Le principe est le même : filtrez l'extension .csv au lieu de .xlsx. Dans la boîte de dialogue Combiner les fichiers, Microsoft indique que l'on règle l'origine du fichier, le délimiteur et la détection du type de données. Restent à traiter l'encodage, les montants et les dates au format français et les codes à garder en texte : c'est l'objet du module 2 de la formation. Microsoft Learn a aussi une page « Combiner des fichiers CSV ».

Liens : Combiner des fichiers CSV dans Power Query (Microsoft Learn) · programme du module 2.

Combien de fichiers peut-on combiner ?

Les pages Microsoft consultées pour ce guide ne fixent pas de nombre maximal de fichiers. La limite pratique est le temps d'actualisation, car chaque fichier est relu à chaque fois, et, si vous chargez le résultat dans une feuille, la taille d'une feuille Excel : 1 048 576 lignes. Au-delà, chargez dans le modèle de données ou regroupez avant de charger.

Combiner les fichiers d'un dossier ou « Ajouter des requêtes » ?

« Ajouter des requêtes » empile des requêtes qui existent déjà, une par source : cela convient pour deux ou trois sources fixes. Le dossier s'adapte tout seul : une agence de plus, c'est un fichier de plus dans le dossier, sans requête à créer.
