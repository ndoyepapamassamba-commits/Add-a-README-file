L'équivalent de RECHERCHEV dans Power Query : fusionner des requêtes

Power Query n'a pas de fonction RECHERCHEV : son équivalent est la fusion de requêtes. Sur une extraction de prêts fictive, ajoutez la zone de l'agence et le segment du produit, listez automatiquement les codes non trouvés et évitez les 4 pièges qui faussent le résultat sans le moindre message d'erreur.

Mis à jour le 22/10/2026 · Données d'exemple 100 % fictives · Excel 2016 ou plus récent, ou Microsoft 365, sous Windows

La réponse en 4 étapes :

  1. Chargez l'extraction et la table de correspondance dans Power Query (Données › À partir d'un tableau ou d'une plage), avec les colonnes de codes en Texte.
  2. Dans l'extraction : Accueil › Fusionner les requêtes, cliquez sur la colonne clé de chaque table, type de jointure Externe gauche. C'est l'équivalent de RECHERCHEV(…;FAUX).
  3. Cliquez sur l'icône Développer de la nouvelle colonne, cochez les colonnes à ramener et décochez Utiliser le nom de colonne d'origine comme préfixe.
  4. Vérifiez que le nombre de lignes n'a pas changé et listez les codes sans correspondance (jointure Anti gauche). Le mois suivant : Données › Actualiser tout.

Sur l'exemple fictif de ce guide : 12 contrats, 2 tables de correspondance, 3 codes produit sans correspondance trouvés automatiquement, dont 2 simples fautes de saisie.

Pourquoi remplacer RECHERCHEV par une fusion de requêtes

Chaque fin de mois, le service reporting de la Banque Fictive de l'Ouest (BFO), une banque imaginaire, reçoit l'extraction des prêts : un contrat par ligne, avec un code agence, un code produit et l'encours. Pour présenter l'encours par zone ou par segment de clientèle, il faut ajouter à chaque ligne la zone de l'agence et le segment du produit, rangés dans deux tables de correspondance. Le réflexe Excel : deux colonnes de RECHERCHEV, par exemple =RECHERCHEV([@code_agence];Agences;3;FAUX) pour la zone.

Cela marche, mais un travail mensuel fait ainsi s'abîme vite :

  • Des formules à étendre : chaque mois, la nouvelle extraction doit recevoir ses colonnes de formules sur toute sa longueur. Quand elle passe de 12 à 5 000 lignes, la moindre ligne oubliée reste vide.
  • Un numéro de colonne figé : le 3 de la formule désigne la troisième colonne de la table. Insérez une colonne avant zone, et la formule renvoie une autre colonne, sans erreur.
  • Des #N/A masqués : pour un code introuvable, RECHERCHEV renvoie #N/A ; on l'habille souvent d'un SIERREUR(…;""), et le contrat disparaît du total par zone sans que personne ne le voie.
  • Le quatrième argument oublié : sans FAUX, RECHERCHEV cherche une valeur approchée. Le support Microsoft le précise pour la correspondance approximative : « Cette méthode est appliquée par défaut si vous n'en spécifiez pas d'autre. »

Dans Power Query, il n'existe pas de formule RECHERCHEV à écrire dans une cellule. L'équivalent est une commande : Fusionner les requêtes (en code M, Table.NestedJoin). Microsoft Learn la définit ainsi : « Une opération de requête de fusion joint deux tables existantes en fonction des valeurs correspondantes d'une ou plusieurs colonnes. » La fusion devient une étape de la requête : à chaque actualisation, elle est rejouée sur la nouvelle extraction, quelle que soit sa longueur, sans formule à recopier.

Étape 1 — Charger les trois tableaux dans Power Query

  1. Ouvrez le classeur, feuille Prets, et cliquez dans le tableau.
  2. Données › À partir d'un tableau ou d'une plage (selon la version, le bouton s'appelle aussi À partir de Tableau/Plage ; sinon Données › Obtenir des données › À partir d'autres sources › À partir d'un tableau ou d'une plage). L'Éditeur Power Query s'ouvre sur une requête nommée Prets.
  3. Regardez l'icône à gauche de chaque en-tête : ABC signifie Texte, 123 Nombre entier, 1.2 Nombre décimal. code_agence et code_produit doivent être en ABC. Si un code affiche 123, cliquez sur l'icône, choisissez Texte, puis Remplacer l'actuelle.
  4. Accueil › Fermer et charger › Fermer et charger dans…, choisissez Créer uniquement la connexion, puis OK.
  5. Recommencez avec le tableau de la feuille Agences, puis avec celui de la feuille Produits.

Pourquoi « connexion uniquement » ? Ces tableaux sont déjà dans le classeur : les charger une seconde fois créerait trois feuilles en double. Les requêtes servent seulement d'entrées aux fusions. Le choix Remplacer l'actuelle a aussi son importance : il change le type de l'étape existante, alors qu'une nouvelle étape convertirait un code déjà devenu 1 en « 1 », sans retrouver ses zéros (voir le piège n° 3).

  • Le volet Requêtes et connexions (Données › Requêtes et connexions) affiche trois requêtes, Prets, Agences et Produits, chacune avec la mention « Connexion uniquement ».
  • Dans l'éditeur, code_agence affiche bien « 001 », « 007 », et non 1 ou 7.

Étape 2 — Fusionner les requêtes : le RECHERCHEV de Power Query

Fusionner deux tables, ici l'extraction et la table des agences, revient à poser une RECHERCHEV sur toute la colonne d'un coup. On garde la requête Prets intacte et on travaille sur une copie liée : Prets servira plus loin au contrôle et à la liste des codes non trouvés.

  1. Dans le volet Requêtes et connexions, clic droit sur Prets › Modifier. L'éditeur s'ouvre.
  2. Dans le volet Requêtes, à gauche, clic droit sur Prets › Référence. Une requête Prets (2) apparaît : renommez-la Prets_enrichis (Paramètres de requête › Propriétés › Nom, à droite).
  3. Requête Prets_enrichis sélectionnée : Accueil › Fusionner les requêtes. La boîte de dialogue Fusionner s'ouvre, avec Prets_enrichis en haut.
  4. Cliquez sur l'en-tête code_agence de cette table. Dans la liste en dessous, choisissez Agences, puis cliquez sur son en-tête code_agence.
  5. Dans Type de jointure, choisissez (ou vérifiez) Externe gauche.
  6. Lisez le message en bas de la boîte de dialogue, puis cliquez sur OK.

Le message en bas de la boîte de dialogue est votre premier contrôle. Microsoft Learn l'annonce ainsi : une fois les colonnes choisies, « un message s'affiche avec un nombre estimé de correspondances en bas de la boîte de dialogue ». Il compte les lignes de la table du haut qui trouvent au moins une correspondance. Ici, il indique 12 lignes sur 12 (la formulation exacte varie selon la version) : tous les codes agence de l'extraction existent dans Agences.

Externe gauche est le bon choix pour remplacer RECHERCHEV : d'après Microsoft Learn, la jointure externe gauche « conserve toutes les lignes de la table de gauche et intègre toutes les lignes correspondantes de la table de droite ». Une ligne sans correspondance reste dans le résultat, avec une valeur null : c'est le #N/A de Power Query, sauf qu'il ne casse aucune somme. Les noms des colonnes clés n'ont pas besoin d'être identiques ; leur type, si (voir le piège n° 3).

Power Query ajoute une colonne Agences qui affiche Table dans chaque cellule : la ou les lignes de Agences trouvées pour ce contrat. Dans la barre de formule, l'étape ressemble à ceci :

= Table.NestedJoin(Source, {"code_agence"}, Agences, {"code_agence"}, "Agences", JoinKind.LeftOuter)

Étape 3 — Développer la colonne fusionnée (l'équivalent de no_index_col)

  1. Cliquez sur l'icône à deux flèches dans l'en-tête de la colonne Agences. Laissez l'option Développer choisie.
  2. Décochez code_agence, déjà présent dans l'extraction ; gardez agence et zone.
  3. Décochez Utiliser le nom de colonne d'origine comme préfixe, sinon les colonnes s'appelleront Agences.agence et Agences.zone. OK.

Ce développement fait le travail de no_index_col, en mieux : les colonnes sont désignées par leur nom, et l'ajout d'une colonne à la table Agences ne décale rien. Dans la barre de formule (le nom de l'étape précédente peut différer) :

= Table.ExpandTableColumn(#"Requêtes fusionnées", "Agences", {"agence", "zone"}, {"agence", "zone"})

Vérifiez maintenant le nombre de lignes, affiché dans la barre d'état en bas de l'éditeur : 15 lignes au lieu de 12. Ce n'est pas une erreur de manipulation : c'est la première anomalie du classeur. Le code 003 figure deux fois dans Agences, si bien que chacun des trois contrats de l'agence Filao (P-1005, P-1006, P-1007) ressort deux fois. L'encours total passe de 173 050 000 à 217 600 000 FCFA : 44 550 000 comptés deux fois. Corrigez tout de suite (l'explication complète est au piège n° 1) :

  1. Dans le volet Requêtes, sélectionnez Agences.
  2. Sélectionnez toutes ses colonnes : clic sur l'en-tête code_agence, puis Maj + clic sur l'en-tête zone.
  3. Accueil › Supprimer les lignes › Supprimer les doublons. Agences passe à 5 lignes.
  4. Revenez sur Prets_enrichis.
  • Agences : 5 lignes, un seul 003.
  • Prets_enrichis : 12 lignes et 6 colonnes (contrat, code_agence, code_produit, encours, agence, zone), toutes avec une agence et une zone.

Étape 4 — Deuxième fusion : fusionner 3 tables, c'est enchaîner les fusions

Il n'y a pas de commande spéciale pour fusionner plusieurs tables : que l'on parle de fusionner 3 tables ou 3 requêtes, chaque table de correspondance donne une fusion de plus, comme chaque RECHERCHEV donnait une colonne de plus. On ajoute maintenant la famille et le segment du produit.

  1. Prets_enrichis sélectionnée : Accueil › Fusionner les requêtes.
  2. Cliquez sur code_produit en haut, choisissez Produits dans la liste, cliquez sur son code_produit. Type de jointure : Externe gauche.
  3. Le message indique cette fois 9 lignes sur 12 : trois contrats ne trouvent pas leur produit. Cliquez sur OK quand même : on veut les voir, pas les perdre.
  4. Développez la colonne Produits : gardez famille et segment, sans préfixe. OK.
  5. Accueil › Fermer et charger. Prets_enrichis est chargée dans une nouvelle feuille.

Et si la clé tient sur deux colonnes ?

Il arrive qu'un code ne suffise pas : un taux qui dépend de l'agence et du produit, par exemple. Avec RECHERCHEV, on crée une colonne qui concatène les deux codes. Dans la boîte de dialogue Fusionner, il suffit de cliquer sur la première colonne, puis de maintenir Ctrl en cliquant sur la seconde ; Power Query numérote la sélection 1, 2. Faites de même dans la table de droite, dans le même ordre. Microsoft Learn insiste : « l'ordre dans lequel vous sélectionnez les colonnes de chaque table doit correspondre », sinon « vous pouvez observer des résultats de jointure incorrects ». En code M, les deux listes de clés s'écrivent {"code_agence", "code_produit"}.

Étape 5 — Lister automatiquement les codes sans correspondance

Pour un premier coup d'œil, filtrez la colonne famille du tableau chargé dans Excel sur (Vides) : les trois contrats apparaissent. Pour un contrôle qui se refait tout seul chaque mois, créez plutôt une requête qui liste les codes à corriger, avec la jointure Anti gauche. Microsoft Learn la décrit comme une jointure « qui n'amène que des lignes de la table de gauche qui n'ont pas de lignes correspondantes dans la table de droite ».

  1. Dans l'éditeur (clic droit sur une requête du volet Requêtes et connexions › Modifier), clic droit sur Prets › Référence. Renommez la nouvelle requête Codes_a_corriger.
  2. Accueil › Fusionner les requêtes : code_produit en haut, Produits et son code_produit en bas, type de jointure Anti gauche. Le message indique 3 lignes sur 12 : pour cette jointure, ce sont les lignes gardées, celles sans correspondance. OK.
  3. Clic droit sur l'en-tête de la colonne Produits, qui ne contient que des tables vides › Supprimer.
  4. Accueil › Regrouper par, option Avancé : regroupement par code_produit ; agrégation Contrats, opération Compter les lignes ; Ajouter une agrégation : Encours, Somme de encours. OK.
  5. Accueil › Fermer et charger.

Cette liste change de nature le contrôle de fin de mois : au lieu de chercher des #N/A dans des milliers de lignes, on lit une table de quelques codes, avec l'encours concerné, avant de publier l'état. Deux des trois lignes viennent d'une faute de saisie que Power Query peut corriger seul ; la troisième, CB, est un vrai manque : il faut compléter la table de correspondance. Les deux cas sont traités au piège suivant.

Les 4 pièges qui faussent le résultat sans prévenir

Aucun de ces pièges ne déclenche de message d'erreur : la requête s'actualise, les chiffres sont simplement faux. Chacun a donc son test de contrôle.

Piège n° 1 — Un doublon dans la table de correspondance multiplie les lignes

RECHERCHEV s'arrête à la première ligne trouvée. La fusion, elle, ramène toutes les lignes correspondantes, et le développement crée une ligne par correspondance. Le code 003 en double l'a montré à l'étape 3 : 15 lignes au lieu de 12, et 44 550 000 FCFA comptés deux fois. Le message de la boîte de dialogue ne vous aide pas : il annonçait 12 correspondances sur 12, parce qu'il compte les lignes de l'extraction qui trouvent au moins un code, pas le nombre de lignes du résultat.

Test de contrôle. Comparez le nombre de lignes avant et après la fusion : il doit être identique (12 et 12). Pour trouver le code fautif, sélectionnez la colonne code_agence de Agences, puis Accueil › Conserver les lignes › Conserver les doublons : seules les lignes dont le code se répète restent affichées. Sur le classeur d'origine, ce test affiche les deux lignes 003 ; après la correction de l'étape 3, il n'affiche plus rien. Supprimez ensuite cette étape de test (la croix à gauche de son nom, dans Étapes appliquées).

Correction. Deux cas :

  • Les lignes sont identiques (une ligne copiée deux fois, comme ici) : Supprimer les doublons sur toutes les colonnes, comme à l'étape 3, est sans risque.
  • Les lignes diffèrent (003 rattaché au Littoral sur une ligne, au Plateau sur l'autre) : ne supprimez pas les doublons sur la seule colonne code_agence. Microsoft Learn prévient que « Power Query ne garantit pas qu'elle conserve la première instance dans un ensemble de doublons lorsqu'elle supprime les doublons ». Power Query ne peut pas savoir quelle zone est la bonne : corrigez la table de correspondance. Pour voir ces codes, Accueil › Regrouper par code_agence avec Compter les lignes, puis filtrez les comptes supérieurs à 1.

Attention aussi à la casse : « Power Query respecte la casse », écrit Microsoft, y compris pour les doublons. « pp » et « PP » ne sont pas des doublons l'un de l'autre : d'où le piège suivant.

Piège n° 2 — Espaces et casse : « pp » n'est pas « PP »

En correspondance exacte, Power Query compare les codes caractère par caractère. Un espace en fin de code, fréquent dans les extractions de systèmes qui complètent les champs à longueur fixe, ou une minuscule saisie à la main suffisent à faire échouer la correspondance. C'est ce qui arrive à P-1004 (pp) et à P-1006 (CT suivi d'un espace).

Test de contrôle. La liste Codes_a_corriger de l'étape 5. Pour voir un espace invisible, sélectionnez la colonne puis Ajouter une colonne › Extraire › Longueur : « CT » suivi d'un espace compte 3 caractères au lieu de 2. Supprimez ensuite cette colonne de test.

Correction, dans les deux tables, sinon le problème se déplace :

  1. Requête Prets : sélectionnez code_produit, puis Transformer › Format › Supprimer les espaces, puis Transformer › Format › MAJUSCULES.
  2. Requête Produits : les mêmes deux commandes sur code_produit.
  3. Accueil › Fermer et charger, puis Données › Actualiser tout.

Les deux commandes créent deux étapes, l'une avec Text.Trim, l'autre avec Text.Upper. Text.Trim retire, selon sa documentation, « tous les espaces blancs de début et de fin » ; il ne touche pas aux espaces au milieu du code. En code M, on peut les réunir en une seule étape (le nom de l'étape précédente peut différer) :

= Table.TransformColumns(#"Type modifié", {{"code_produit", each Text.Upper(Text.Trim(_)), type text}})
  • Codes_a_corriger : une seule ligne, CB, 1 contrat, 14 600 000 FCFA.
  • Prets_enrichis : P-1004 et P-1006 ont désormais une famille et un segment (Consommation, Particuliers ; Trésorerie, Entreprises). La fusion trouve 11 correspondances sur 12.

Reste CB, un produit qui n'est pas dans la table. Ajoutez-le dans le tableau Excel Produits, sur la ligne juste sous le tableau : CB, Investissement, Entreprises. Le tableau s'agrandit tout seul. Puis Données › Actualiser tout : Codes_a_corriger n'affiche plus que ses en-têtes, et les 12 contrats ont une famille et un segment (Entreprises : 6 contrats, 97 100 000 ; Particuliers : 6 contrats, 75 950 000).

Piège n° 3 — Des clés de types différents : « 001 » n'est pas 1

Pour Power Query, le texte « 001 » et le nombre 1 sont deux valeurs différentes. Si code_agence est en Texte dans l'extraction et en Nombre entier dans Agences, aucun code ne correspond. Microsoft Learn le dit clairement : « les colonnes doivent être du même type de données, sinon l'opération de fusion risque de ne pas générer de résultats corrects ».

Ce piège vient souvent d'Excel lui-même : tapez 001 dans une cellule au format Standard, et Excel enregistre le nombre 1. Un format personnalisé « 000 » le réaffiche « 001 », mais la valeur reste 1, et c'est elle que lit Power Query. Il peut venir aussi de la détection automatique des types, qui, selon Microsoft, se fonde sur les 200 premières lignes et peut se tromper ; et, ajoute la même page, « un type incorrect ne produit pas toujours d'erreurs ».

Test de contrôle. Avant chaque fusion, les deux colonnes clés doivent afficher la même icône (ABC pour des codes). Dans la boîte de dialogue Fusionner, un nombre de correspondances anormalement bas, ou nul, est le signal d'alarme. Faites l'essai : passez code_agence de Agences en Nombre entier ; les codes deviennent 1, 2, 3, 4 et 7, la fusion ne trouve plus aucune des 12 lignes, et agence et zone sont vides partout, sans message. Supprimez ensuite cette étape d'essai (la croix à gauche de son nom, dans Étapes appliquées).

Correction. Mettez les colonnes clés en Texte des deux côtés, en remplaçant l'étape de type existante. Si les zéros sont déjà perdus à la source (des codes saisis comme des nombres), reconstituez-les avec Text.PadStart, qui complète un texte à gauche jusqu'à la longueur voulue :

= Table.TransformColumns(#"Type modifié", {{"code_agence", each Text.PadStart(Text.From(_), 3, "0"), type text}})

Cette ligne transforme 1 en « 001 » et laisse « 001 » intact. Elle suppose des codes agence toujours sur 3 chiffres : adaptez la longueur à vos codes.

Piège n° 4 — Pas d'équivalent direct de RECHERCHEV(…;VRAI)

Avec VRAI, RECHERCHEV sert souvent à classer un montant dans des tranches d'un barème. La fusion n'a pas d'équivalent : elle ne compare que des valeurs égales. La case Utiliser la correspondance approximative pour effectuer la fusion, en bas de la boîte de dialogue, ne fait pas ce travail. Elle compare des textes qui se ressemblent (des noms mal orthographiés, par exemple), avec un seuil de similarité qui vaut 0,80 par défaut, et Microsoft précise que « la correspondance approximative est uniquement prise en charge pour les opérations de fusion sur les colonnes de texte ». Elle ne sait donc pas qu'un encours de 9 800 000 tombe entre 5 et 20 millions. Pour des codes, elle est même dangereuse : la page Microsoft Learn consacrée à la correspondance approximative indique qu'elle « peut ignorer les différences telles que la casse, l'ordre des mots et la ponctuation », et chaque rapprochement serait à vérifier.

Pour des tranches, utilisez une colonne conditionnelle. Dans le volet Requêtes, clic droit sur Prets_enrichis › Référence, nommez la copie Prets_tranches, puis Ajouter une colonne › Colonne conditionnelle. Nouveau nom de colonne : Tranche. Première clause : si encours est inférieur à 5000000, sortie « Moins de 5 M ». Ajouter une clause : si encours est inférieur à 20000000, sortie « 5 à 20 M ». Sinon : « 20 M et plus ». D'après Microsoft Learn, « chaque clause conditionnelle est testée sur l'ordre indiqué dans la boîte de dialogue, de haut en bas » : rangez les bornes dans l'ordre croissant, comme le barème d'une RECHERCHEV approchée. La colonne créée n'a pas de type : passez-la en Texte. En code M :

// Requête Prets_tranches : l'extraction enrichie, avec sa tranche d'encours
let
    Source = Prets_enrichis,
    // Les clauses sont testées dans l'ordre : la première vraie l'emporte
    AvecTranche = Table.AddColumn(Source, "Tranche", each
        if [encours] < 5000000 then "Moins de 5 M"
        else if [encours] < 20000000 then "5 à 20 M"
        else "20 M et plus", type text)
in
    AvecTranche

Regroupez ensuite Prets_tranches par Tranche (Accueil › Regrouper par, avec Compter les lignes et la Somme de encours) pour vérifier :

  • Moins de 5 M : 3 contrats, 10 100 000 FCFA.
  • 5 à 20 M : 5 contrats, 56 200 000 FCFA.
  • 20 M et plus : 4 contrats, 106 750 000 FCFA.

Le module gratuit « Calculer l'ancienneté des impayés avec Power Query » applique la même logique aux jours de retard : il range chaque prêt dans une tranche d'ancienneté, puis regroupe l'encours et les impayés par tranche, avec le code M complet et les résultats attendus.

Le code M complet, pièges corrigés

Voici les six requêtes de l'exemple, telles qu'on peut les écrire une fois les pièges connus. Elles portent les mêmes noms que celles créées à la souris. Si vous avez suivi les étapes, remplacez le code de chaque requête (Accueil › Éditeur avancé). Sinon, partez d'une copie du classeur téléchargé : créez chaque requête par Données › Obtenir des données › À partir d'autres sources › Requête vide, ouvrez Accueil › Éditeur avancé, collez le code, puis renommez la requête (Paramètres de requête › Propriétés › Nom). Chargez Prets, Agences et Produits en connexion uniquement, les trois autres dans des feuilles.

// Requête Prets (connexion uniquement) : l'extraction, clés nettoyées
let
    Source = Excel.CurrentWorkbook(){[Name = "Prets"]}[Content],
    // Clés en texte, sans espace au début ni à la fin (pièges 2 et 3) ;
    // un code agence lu comme le nombre 1 redevient "001"
    Cles = Table.TransformColumns(Source, {
        {"code_agence", each Text.PadStart(Text.Trim(Text.From(_)), 3, "0"), type text},
        {"code_produit", each Text.Upper(Text.Trim(Text.From(_))), type text}}),
    Types = Table.TransformColumnTypes(Cles,
        {{"contrat", type text}, {"encours", type number}})
in
    Types
// Requête Agences (connexion uniquement) : la table de correspondance des agences
let
    Source = Excel.CurrentWorkbook(){[Name = "Agences"]}[Content],
    Cles = Table.TransformColumns(Source, {
        {"code_agence", each Text.PadStart(Text.Trim(Text.From(_)), 3, "0"), type text}}),
    Types = Table.TransformColumnTypes(Cles,
        {{"agence", type text}, {"zone", type text}}),
    // Piège 1 : retire les lignes identiques. Deux lignes différentes pour un même code
    // restent : le contrôle les signale, et c'est la table Excel qu'il faut corriger.
    SansDoublons = Table.Distinct(Types)
in
    SansDoublons
// Requête Produits (connexion uniquement) : la table de correspondance des produits
let
    Source = Excel.CurrentWorkbook(){[Name = "Produits"]}[Content],
    Cles = Table.TransformColumns(Source, {
        {"code_produit", each Text.Upper(Text.Trim(Text.From(_))), type text}}),
    Types = Table.TransformColumnTypes(Cles,
        {{"famille", type text}, {"segment", type text}}),
    SansDoublons = Table.Distinct(Types)
in
    SansDoublons
// Requête Prets_enrichis : l'extraction + agence, zone, famille, segment
let
    Source = Prets,
    // Fusion n° 1 (le premier « RECHERCHEV ») : Externe gauche = toutes les lignes
    // de l'extraction, enrichies quand le code existe dans Agences
    FusionAgences = Table.NestedJoin(Source, {"code_agence"},
        Agences, {"code_agence"}, "Agences", JoinKind.LeftOuter),
    // Développement : les colonnes voulues, par leur nom (l'équivalent de no_index_col),
    // avec leur nom final, sans préfixe
    AvecAgence = Table.ExpandTableColumn(FusionAgences, "Agences",
        {"agence", "zone"}, {"agence", "zone"}),
    // Fusion n° 2 : la famille et le segment du produit
    FusionProduits = Table.NestedJoin(AvecAgence, {"code_produit"},
        Produits, {"code_produit"}, "Produits", JoinKind.LeftOuter),
    AvecProduit = Table.ExpandTableColumn(FusionProduits, "Produits",
        {"famille", "segment"}, {"famille", "segment"}),
    // L'ordre des lignes n'est pas garanti après une fusion : on trie à la fin
    Tri = Table.Sort(AvecProduit, {{"contrat", Order.Ascending}})
in
    Tri
// Requête Codes_a_corriger : les codes de l'extraction absents d'une table de correspondance
let
    // Anti gauche : seulement les contrats sans correspondance
    SansAgence = Table.NestedJoin(Prets, {"code_agence"},
        Agences, {"code_agence"}, "Agences", JoinKind.LeftAnti),
    CodesAgence = Table.Group(SansAgence, {"code_agence"}, {
        {"Contrats", each Table.RowCount(_), Int64.Type},
        {"Encours", each List.Sum([encours]), type nullable number}}),
    ListeAgences = Table.AddColumn(Table.RenameColumns(CodesAgence, {{"code_agence", "Code"}}),
        "Table à compléter", each "Agences", type text),

    SansProduit = Table.NestedJoin(Prets, {"code_produit"},
        Produits, {"code_produit"}, "Produits", JoinKind.LeftAnti),
    CodesProduit = Table.Group(SansProduit, {"code_produit"}, {
        {"Contrats", each Table.RowCount(_), Int64.Type},
        {"Encours", each List.Sum([encours]), type nullable number}}),
    ListeProduits = Table.AddColumn(Table.RenameColumns(CodesProduit, {{"code_produit", "Code"}}),
        "Table à compléter", each "Produits", type text),

    // Une seule liste, vide quand tout est correct
    Liste = Table.Combine({ListeAgences, ListeProduits}),
    Ordre = Table.ReorderColumns(Liste, {"Table à compléter", "Code", "Contrats", "Encours"})
in
    Ordre
// Requête Controle_Fusion : quatre chiffres à relire après chaque actualisation
let
    LignesAvant = Table.RowCount(Prets),
    LignesApres = Table.RowCount(Prets_enrichis),
    EcartEncours = List.Sum(Prets_enrichis[encours]) - List.Sum(Prets[encours]),
    SansAgence = List.Count(List.Select(Prets_enrichis[zone], each _ = null)),
    SansProduit = List.Count(List.Select(Prets_enrichis[famille], each _ = null)),
    Resultat = #table(
        type table [Contrôle = text, Valeur = number, Statut = text],
        {
            {"Lignes ajoutées par la fusion (doublons)", LignesApres - LignesAvant,
                if LignesApres = LignesAvant then "OK" else "À vérifier"},
            {"Écart d'encours après fusion (FCFA)", EcartEncours,
                if EcartEncours = 0 then "OK" else "À vérifier"},
            {"Contrats sans agence trouvée", SansAgence,
                if SansAgence = 0 then "OK" else "À vérifier"},
            {"Contrats sans produit trouvé", SansProduit,
                if SansProduit = 0 then "OK" else "À vérifier"}
        })
in
    Resultat

Les deux fonctions qui font le travail :

  • Table.NestedJoin joint les lignes de deux tables « en fonction de l'égalité des valeurs des colonnes clés » et range le résultat dans une nouvelle colonne de tables. Sa documentation précise : « Par défaut, une jointure externe gauche est effectuée si aucun joinKind n'est spécifié. » On l'écrit quand même : JoinKind.LeftOuter se lit mieux. JoinKind.LeftAnti donne la jointure Anti gauche.
  • Table.ExpandTableColumn développe ces tables en colonnes. Le troisième argument choisit les colonnes, le quatrième leur donne leur nom final : c'est lui qui évite le préfixe Agences. devant les noms de colonnes.
  • Prets_enrichis : 12 lignes, 173 050 000 FCFA, P-1004 et P-1006 déjà complétés grâce au nettoyage des clés.
  • Codes_a_corriger : une ligne, Produits, CB, 1 contrat, 14 600 000.
  • Controle_Fusion : les trois premières lignes valent 0, avec le statut « OK » ; la ligne « Contrats sans produit trouvé » vaut 1, avec le statut « À vérifier » (le contrat P-1008, code CB). Après l'ajout de CB à la table Produits et Données › Actualiser tout : quatre « OK » et une liste vide.

Pour le mois suivant, collez la nouvelle extraction dans le tableau Prets (mêmes en-têtes), puis Données › Actualiser tout, et lisez Controle_Fusion avant d'utiliser les chiffres.

Questions fréquentes

Peut-on fusionner sur deux colonnes ?

Oui. Dans la boîte de dialogue Fusionner, cliquez sur la première colonne puis maintenez Ctrl en cliquant sur la seconde ; faites de même dans la table de droite. Power Query numérote la sélection (1, 2). Microsoft précise que « l'ordre dans lequel vous sélectionnez les colonnes de chaque table doit correspondre », sinon les résultats peuvent être incorrects. C'est l'équivalent d'une RECHERCHEV sur une clé concaténée, sans colonne de concaténation à créer.

Pourquoi j'obtiens plus de lignes qu'avant ?

Parce qu'un code apparaît plusieurs fois dans la table de correspondance. RECHERCHEV s'arrête à la première ligne trouvée ; la fusion ramène toutes les lignes correspondantes, et le développement crée une ligne par correspondance. Sur l'exemple, le code 003 en double fait passer l'extraction de 12 à 15 lignes et l'encours de 173 050 000 à 217 600 000 FCFA. Repérez le code avec Accueil › Conserver les lignes › Conserver les doublons, puis supprimez les lignes identiques ou corrigez la table.

Que faire des codes non trouvés ?

Les lister, pas les supprimer. Une requête Anti gauche donne les contrats dont le code est absent de la table de correspondance, et un regroupement par code donne le nombre de contrats et l'encours concernés. Ensuite, deux cas : une faute de saisie (espace, minuscule) se corrige dans Power Query avec Supprimer les espaces et MAJUSCULES ; un vrai code manquant, comme CB dans l'exemple, s'ajoute à la table de correspondance, puis Données › Actualiser tout.

La fusion fonctionne-t-elle entre deux classeurs ?

Oui. Créez une requête par classeur (Données › Obtenir des données › À partir d'un fichier › À partir d'un classeur), puis fusionnez-les comme ici : peu importe d'où viennent les requêtes. À chaque actualisation, Power Query relit les deux fichiers : ne les déplacez pas. Comme les données viennent de deux sources, Excel peut demander leurs niveaux de confidentialité (Privé, Organisationnel, Public), qui servent, selon Microsoft, à éviter de « combiner par inadvertance des données ».

Fusionner ou ajouter des requêtes ?

Fusionner ajoute des colonnes : c'est l'équivalent de RECHERCHEV. Ajouter des requêtes empile des lignes : c'est l'équivalent d'un copier-coller de deux extractions l'une sous l'autre. Pour empiler les fichiers de plusieurs agences, voyez le guide Combiner plusieurs fichiers Excel en un seul avec Power Query.
